## 1. 执行范围与不可改动的边界

### 1.1 用户已明确的要求

- 只做前端单机和 P2P，不实现 Python 游戏后端、WebSocket 新玩法、新 TTS 后端或代理服务。
- 在现有莲花麻将基础上新增血流，增加第 3 节的 16 种常规番型；保留原特殊手。十三幺基础 16 倍，加入硬胡 ×2。
- 不增加双字顺、三字顺、四字顺、全顺、七字齐等新番型；现有字牌顺子仍是合法面子。
- 复用现有动作报声代码、音频资源及角色音色路由。不新增一套“我胡了”语音，不重写普通出牌 / 吃碰杠报声策略，不让同一动作重复播两次。
- 局内胡牌只有现有动作报声、番型、分数、特效和盖楼；首次胡、大番、多响、逆转均不触发感言或付款者反应。
- 全桌感言只在整局结束后启用，且仅限 `llm`、`llmAnime` 主题；其他三个主题无感言气泡、感言语音及相关 TTS 请求。
- “莲花”只表示地名与玩法来源；不派生花卉符号、地域风格或世界观。五主题沿用各自概念。

### 1.2 本版实施默认值

以下由前面的建议收敛成可编码的默认配置，不虚称用户已逐条确认；实现时集中配置，不分散写死。若用户调整，更新版本与测试预期，不另行猜测。

| 项目 | 本版默认 |
|---|---|
| 新规则键 / 显示名 | `lotus-blood-flow` / 莲花麻将·血流 |
| 启用范围 | 新血流模式；原 `lotus-classic`、`lotus-legacy` 不自动获得新计分 |
| 底分 / 初始分 / 封顶 | 10 / 2000 / 每次胡牌每位付款人最终 64 倍 |

- 保留 136 张实体牌、两次骰子、双精和白板受限替代。当前前后端均移出整墩两张，实际发摸序列为 134 张；指示牌与底张分别参与守恒，底张不公开。

## 3. 规则与计分规范

### 3.1 番型目录

除单独说明外，以下条件都在同一合法分解中判断，包含全部副露、将牌和本次胡牌张。普通同牌杠可以替代刻子；风杠不能替代同牌刻子。

| ID | 名称 | 基础倍数 | 判定 |
|---|---|---:|---|
| `pure-suit` | 清一色 | 4 | 恰好一种数牌花色，无字牌 |
| `mixed-suit` | 混一色 | 2 | 恰好一种数牌花色与字牌同时存在 |
| `all-triplets` | 碰碰胡 | 2 | 四副同牌刻 / 普通杠加将；无数牌顺、字牌顺、风杠 |
| `little-three-dragons` | 小三元 | 4 | 两种箭牌刻 / 普通杠，第三种箭牌作将 |
| `big-three-dragons` | 大三元 | 8 | 中发白三种各一副刻 / 普通杠 |
| `little-four-winds` | 小四喜 | 8 | 三种风刻 / 普通杠，第四种风牌作将 |
| `big-four-winds` | 大四喜 | 16 | 四种风牌各一副刻 / 普通杠 |
| `nine-gates` | 九莲宝灯 | 16 | 无任何吃碰杠；同花色 `1112345678999` 加同色任意一张，按最终牌形判定 |
| `all-green` | 绿一色 | 16 | 仅二三四六八条与发，组成合法和牌；不强制有发 |
| `pure-terminals` | 清幺九 | 16 | 仅数牌一九的四副刻 / 普通杠加将 |
| `mixed-terminals` | 混幺九 | 4 | 仅数牌一九与字牌的四副刻 / 普通杠加将，数牌和字牌均须有 |
| `three-concealed-triplets` | 三暗刻 | 4 | 至少三副暗刻 / 普通暗杠；其余面子可为顺子 |
| `four-concealed-triplets` | 四暗刻 | 8 | 四副暗刻 / 普通暗杠加将 |
| `all-honors` | 字一色 | 8 | 完整和牌全为字牌，允许现有字顺与风杠 |
| `three-kongs` | 三杠 | 8 | 至少三副已成功声明的四张同牌杠，另有合法面子和将 |
| `four-kongs` | 四杠 | 16 | 四副已成功声明的四张同牌杠加将 |

原特殊手：平胡 1、七对 2、十三烂 2、七星十三烂 4、十三幺 16。七对保持当前合法性口径，可叠牌种属性；十三烂、七星十三烂、十三幺作为独立特殊手，不追加面子 / 牌种番，但可按实际自然成立条件获得硬胡。

### 3.2 精牌与硬胡

- 可替代分解：精牌可代表任意牌；白板仅可代表本局精牌牌面或白板本身。已落地的吃碰杠不重新解释。
- 自然分解：完全按真实牌面成立，精牌与白板均不用替代能力，硬胡 ×2。物理上含精不等于一定软胡。
- 各分解分别完成番型组合、硬胡、自摸等事件与封顶后，取最高合法支付；同分优先自然分解，再按稳定番型 ID 顺序，确保两端显示稳定。
- 不能从分解 A 取得硬胡资格，再给分解 B 的替代高番 ×2。
- 外来精牌只消费该张牌的普通身份；不能将暗手中所有同种精牌一起降为普通牌。
- 虚拟代表牌不改变实体牌库数量。当前规则允许的绝张替代口径保留；不得在新评分器内顺手改变旧模式合法性。
- 每次血流胡牌都重算分解、硬胡与事件标记，不继承首胡标签。

### 3.3 明暗与杠的边界

- 点炮 / 抢杠牌补成刻子时，该刻不算暗刻；补将不影响另外四副暗刻。按本次胡牌张的合法归属分别评分。
- 普通暗杠算暗刻，碰、直杠、补杠不算；不能以 UI 是否亮牌判断明暗。
- 三杠 / 四杠只数已提交普通杠：风杠、手中四张未声明、pending 补杠、被抢的补杠均不计。碰升补杠仍是一副。
- 风杠仍占一个结构面子，有四张字牌实体和原有即时杠分，但不算暗刻、同牌刻或本轮三 / 四杠。

### 3.4 组合、事件与支付

排除关系：四暗刻包含三暗刻和碰碰胡；四杠包含三杠和碰碰胡；大四喜、清幺九、混幺九包含碰碰胡；九莲包含清一色。大小三元、大小四喜按定义互斥。小四喜和大三元不必全刻，因此实际满足时允许另计碰碰胡。

计算步骤：

1. 每个分解匹配番型，去除被包含项；`M = 1 + Σ(weight - 1)`。
2. 事件倍率 E：普通点炮 1，自摸 2，抢普通补杠 2，杠后自摸 4。它们按来源互斥分支取值，不重复贴自摸标签收三家钱。
3. 天胡 / 地胡默认与本次普通结果择高：该分解的事件后倍率 `Q = max(M × E, 8)`；非开局事件 `Q = M × E`。开局加成不另行连乘，首胡批次结束后关闭后续天胡 / 地胡窗口。
4. 该分解自然成立时 H=2，否则 H=1。单家支付 `10 × min(Q × H, 64)`。
5. 每位赢家选择合法最高支付；点炮 / 抢杠只向来源玩家收，自摸向另外三家收。多响统一提交聚合收付向量。
6. 即时杠分单独结算，不乘硬胡或重复胡次数：直杠来源付 B，补杠其他三家各付 B，暗杠 / 风杠其他三家各付 2B。

算术验收：硬胡十三幺点炮 320，自摸每家 640 / 总收 1920；硬胡清一色 + 碰碰胡自摸为 20 倍，每家 200 / 总收 600。已经封顶后不再额外翻倍。

## 4. 状态与协议契约

新类型建议放 `src/game/variants/lotus/bloodFlow/types.ts`，以可选能力接入 `GamePort`，不破坏旧模式必需字段。

| 类型 | 必备字段 / 责任 |
|---|---|
| `BloodFlowRuleConfig` | 规则 ID、版本、权重、硬胡、事件倍率、封顶、锁手及场制 |
| `WinEvaluationInput` | 暗手、完整副露、胡牌张及来源、精牌上下文、开局 / 杠摸标记 |
| `WinEvaluation` | 最佳分解、计分项、排除理由、精牌分配、自然成立证据、封顶前后倍率、支付 |
| `ClaimWindow` | 局 ID、窗口 ID、状态版本、来源牌事件、候选席位、独立决定、统一截止时间 |
| `WinBatch` | 批次 ID、来源事件、来源席位、赢家数组、四家 delta、提交后分数、下一动作信息 |
| `WinRecord` | 赢家、序号、源牌引用、公开番型和倍率、收付；完整暗手证据仅权威端保存 |
| `BloodFlowSeatState` | 胡牌次数、锁定标记、首次胡序号、记录引用 |
| `BloodFlowRoundResult` | 结束原因、开局 / 结束积分、胡杠净分、胡牌统计、排名、公开流水 |

### 4.1 事件不变量

- 一个源牌事件最多归档一张实体牌；多响有多个展示记录引用，不能复制牌库实体。
- 一个窗口内每席最多胡一次；重复消息、迟到 AI / LLM 结果或超时回调不能再次提交。
- 每次支付四家之和为零；整局净分等于全部已提交胡牌与杠分。
- 136 张物理牌守恒；翻精两张、牌墙、暗手、副露、弃牌和胡牌归档均纳入。有效手牌张数按暗手 + 3 × 结构面子数判断，杠的额外实体单列。
- 公共事件不含暗手、完整精牌分配或牌墙顺序；全局权威输入不能直接送给 AI / LLM。
- 新模式局内不能调用旧 `endGame` 终局时间线、不能设置全桌 `revealHands=true`、不能发送 `round_settled`。
- 动画与声音不负责积分提交、发牌、锁手或推进规则。

### 4.2 续行表

| 当前事件 | 提交后实体与手牌 | 下一动作 |
|---|---|---|
| 自摸 | 本次摸牌归档，剩余暗手锁定 / 保持锁定 | 赢家下家摸牌 |
| 点炮多响 | 弃牌只归档一次，各赢家手牌不永久加牌 | 出牌者下家摸牌 |
| 抢补杠多响 | 原碰保留，第四张归档；不补牌、不收该次杠分 | 被抢者下家摸牌 |
| 无人胡 | 正常询问杠、碰、吃；无响应才推进 | 按既有动作规则 |
| 锁手后自摸过胡 | 仅能打出本次摸牌，其他人照常响应 | 正常弃牌流程 |
| 最后摸牌 / 弃牌 | 完成所有本次胡响应；无牌可补时禁止新杠 | 结算本局；不再开启无意义的吃碰循环 |

天胡用开局明确记录的第 14 张归档。最后一张牌有人胡也必须把批次结算完成，再做整局汇总，不能漏掉最后多响。
