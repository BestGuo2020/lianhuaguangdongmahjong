# 路线说明与实际候选一致性修复

## 已确认的缺陷

69b249d1 回放中，58次请求使用“已承诺大牌路线，候选不会出现胡、吃碰杠”的固定说明，其中10次实际仍保留胡／吃／碰候选，5次包含胡。东1局窗口278座位3尤其明确：推荐A0胡，但说明声称已经放弃小胡；模型实际选择A4弃三条。

输入矛盾成立，不等于已经证明它造成10次收益损失。修复不据本场名次调整策略。

## 修改

路线说明从 `buildBloodFlowDecisionInput` 的真实输出生成：

- 列出实际保留的动作类型。
- 按动作类型列出路线实际筛除的候选数量；筛掉一种吃法不再被描述为所有吃牌都不可用。
- 胡仍在候选中时明确说“胡牌仍可选择”；仅在路线实际移除胡且胡不再可选时说明已移除胡。
- 本地推荐只引用实际存在的候选ID和动作类型。
- 删除“已决定放弃小胡”“只需要选择怎么弃牌”及将所有路线一概称为“十六至三十二倍级”的固定断言。
- 未应用路线限制时不添加路线说明，没有移除动作时不编造移除原因。

提示词版本由 `bloodFlow-decision/v1` 升至 `v2`，旧回放中的v1仍按历史数据保留。候选筛选、候选排序、推荐算法、1.2阈值、末张保护和额度暂停均未调整。

## 复现与回归

通过原始开局与命令严格重放，导出10个窗口的单座公开视角到 `src/game/llm/fixtures/bloodFlowRoutePrompt.json`，不含对手暗手或未来牌墙。保留回放中的候选标签与推荐编号作为独立期望值。

修复前10项均因旧说明矛盾失败；修复后10项全部通过，候选标签、顺序及推荐编号与原回放一致。另覆盖“同类候选部分移除”“没有移除动作”“无有效推荐”“未启用路线限制”等边界。路线、EV与LLM运行时定向回归共46项通过。

全量前端195个测试文件、1991项通过，原有1文件／2项跳过；Vue类型检查与生产构建通过（保留已有大chunk提示）。

真实worker东风场、半庄场2项通过；三个主题下的LLM可用／不可用对局3项通过，并在模拟供应商收到的真实请求上断言候选与路线说明一致。未调用真实付费模型。

浏览器测试适配记录：最初三个LLM用例因旧断言把所有白板都当成受保护精牌而失败；已有规则和单元测试允许非精白板参与弃牌比较，故将保护对象改为实际jokerTiles，并添加本次提示词一致性断言，重跑3项全部通过（44.6秒）。未为通过测试修改生产弃牌策略。

修复仅保证输入一致性，不宣称已经提高模型平均牌力。
