# 首胡／改张反事实评估（2026-09-20）

## 本轮问题与预先固定的口径

目的：定位本地 AI 在「首胡自摸时立即锁手还是改张」上的损失来源。只做离线评估，不修改生产策略、计分、候选合法性或联机逻辑；无 LLM API 请求。

本轮捕获每个基线来源牌局、每个座位的**第一个未锁手且可自摸胡的窗口**。包括杠上开花，不含已锁手的续胡，也不含点炮／抢杠首胡；先通过点炮锁手的座位不会进入本轮样本。未遇到此类窗口的来源牌局计入采样总数，不伪造窗口。每个来源牌局最多四个窗口，四个座位全部覆盖，庄家按种子序号轮换。

在查看任何续打结果之前，仅根据该座位视图固定以下候选：

1. 立即胡牌。
2. 当前生产 AI 的真实选择。
3. 现有连胡估值排序最靠前的两个不同弃牌牌面，要求弃后仍有听口，并通过当前 AI 的精牌保护／防守过滤。
4. 移除胡／过／杠后，由当前 AI 在可弃牌中选择的一张（继续发育对照）。

相同牌面的弃牌合并，保留全部候选角色。这个候选集合并不穷举全部可行打法；尤其不代表已经找到最佳非胡动作。一次强制候选动作之后，四家均恢复原有本地 AI，直到牌墙耗尽，以**窗口时刻到终局的净分**为主指标，同时拆出胡牌收入、付款、弃牌点炮付款与杠净分。净分必须等于胡牌收入减付款加杠净分。

## 两类续打与信息边界

- **原牌墙重放**：每个候选沿原牌墙续打。当前 AI 候选的最终分数必须与未分叉的基线原局精确相同，否则整批失败。原牌墙结果单独保留，不混入随机墙均值。
- **配对重排**：每个窗口用固定随机种子多次重排剩余牌墙；同一重复中所有候选共用相同牌墙。保留三家的当前暗手、公开历史、锁手状态、番型、牌墙牌面总量、翻精暗牌及一切引擎账本。

这是**条件于真实对手暗手及剩余牌墙构成的离线诊断**，并非从玩家公开信息推导出的隐藏牌后验；原暗手不能被候选选择或后续 AI 读取。重排不改变任何座位的当前可见视图，且不会破坏过去的观测约束；未来从重排后的真实引擎状态自然演化。不同来源种子提供不同的暗手场景，但不等于对同一窗口积分了全部隐藏手牌的不确定性。

所以不能把这里按续打结果选出的赢家接到线上，也不能把条件收益当作可部署策略收益。若发现稳定的损失类别，下一阶段需要公开信息可计算的选择器和独立的完整对局对抗验收。

## 统计与复现底座

- 当前规则配置、AI 配置、动作优先级及其 SHA-256、代码提交和 `src/game` 源码指纹都随批次落盘；同一次运行结束时检查源码未改变。
- 每个窗口保存完整引擎检查点（Node v8 二进制，含 Map 和私有记账）、候选计划及逐次续打数据；每完成一个来源牌局就写进度和结果。
- 先在窗口内平均配对差，再在来源牌局内平均，最后对**来源种子整组 bootstrap**，每个有合格窗口的来源牌局等权。重复牌墙和同局多个座位不是独立牌局。
- 多个候选／分组的区间是探索性区间，没有做多重比较校正。不能事后挑最优候选后，把同一批样本的收益当作泛化收益。
- 独立确认批次使用不同的种子范围，沿用相同采样规则和候选定义；不基于发现批次调整参数。
- 连胡估值与实际收入的比较为辅助诊断：现有估值有 `chainHorizon`，实测收入统计完整剩余牌局，二者时间目标不同，不能机械地把比值变成校准系数。

独立对战底座 `pairedMatch` 支持一个候选策略对三个基线，每个种子轮换候选的四个座位，并与相同发牌的全基线结果配对。基线对基线的 A/A 必须逐项差值为零。未来策略验收以候选座位净分和配对增量为主，不使用整桌净分绝对值推断强弱。


## 实测结果

**结论：保留现有改张能力；本轮没有找到稳定优于当前 AI 的通用候选替换，但找到可复现的残局路线拒胡损失。优先试验局部的路线可兑现性约束，而不是整体调高／调低首胡门槛。**

| 发现 | 2139.6 | 271.1 |
| 独立确认 | 1814.5 | 371.5 |

这里是窗口等权的描述性均值；实际值扣除了首次立即胡收入，未扣付款，覆盖完整剩余牌局。估值量级明显偏大，值得后续校准，但二者时间目标不同，不能把这两个比值直接乘回策略。更不能从「估值偏大」推出「改张不划算」——主指标恰好表明，很多窗口的改张确实比立即锁手更赚。

### 定向复核：残局拒胡的直接触发点是大牌路线，而非改张 EV 门槛

冒烟种子 `950002` 的两个窗口在结果查看后被选为定向案例，不加入独立批次的统计推断。

| 窗口 | 剩余墙 | 落后最高分 | 当前行为 | 去掉大牌路线后的当步选择 | 拒胡相对立即胡的剩余净分差 |
|---|---:|---:|---|---|---:|
| 座位 0 | 3 | 3,400 | 打 6 筒 | 胡 | **−123.33**（穷举全部 6 种剩余牌墙顺序，6/6 为负） |
| 座位 2 | 13 | 1,990 | 打 6 筒 | 胡 | **−120.16**（新增 64 条配对随机墙，64/64 为负；墙序 Monte Carlo SE 0.16） |

两个窗口立即自摸总收入均为 60 点。净分差还包含后续付款、连胡等影响，因此不等于简单损失 60 点。两个分支的剩余净分都可能为负；「更好」是少亏，不是保证获利。

检查点上的机制复核：

1. `narrowActionsToRoute` 识别为碰碰胡路线。
2. `wallOk` 为假，但 `scoreDeficit >= minDeficitForCommit`（默认 300）为真，落后条件绕过了墙余门槛。
3. 路线收益达到 `immediateWinPayment × declineWinRatio`，于是**直接撤掉胡候选**。
4. 对相同座位视图，仅关闭大牌路线，当前本地 AI 即选择胡牌。未改变评分、手牌或计分规则。

所以这两例应优先归为**大牌路线的残局可兑现性缺口**，而非笼统地归为连胡估值偏大。小样本不能支持关闭整套大牌路线，也不能推出「所有残局都应该立即胡」。下一步应单独验证「落后时仍保留最低完成机会约束」之类的局部策略，再做完整对局对抗。

复现这两个案例：先运行冒烟，再运行：

```powershell
$env:BF_CF_RESAMPLE='1'
$env:BF_CF_CASE_TAG='smoke'
$env:BF_CF_CASES='950002-0,950002-2'
$env:BF_CF_CASE_SAMPLES='64'
node node_modules/vitest/vitest.mjs run --dir scripts blood-flow-counterfactual-resample.test.ts
```

墙余 ≤6 时枚举不同牌面顺序，其他窗口按 `BF_CF_CASE_SAMPLES` 重排。输出中的区间只描述**固定暗手下的墙序不确定性**；枚举完全部顺序时没有墙序抽样误差，但仍不消除未知暗手和案例选择偏差。
