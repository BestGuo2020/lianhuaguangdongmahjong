# 听牌硬优先是否需要调整：冻结验证方案（2026-09-20）

## 唯一候选策略

仅调整血流普通 AI 在「当前未听，吃／碰后能听」时的准入：**听牌之后的综合分必须严格高于过牌基线**，才允许吃／碰。综合分仍使用现有听牌奖励、听口、进张、番型潜力和弃牌风险，不重新调权重，也不把该分数当作真实预期净分。

保留既有的候选弃牌排序；本来已经听牌时的比较、两边都未听时不开副露的限制、杠／胡优先级、两个已接入的修复全部不变。该最小改动只增加一个否决条件，不把整个游戏的排序器改成“综合分优先”。

开关 `claimReadyNetGuard`：验证阶段默认关闭，由构建变量 `VITE_BLOOD_FLOW_CLAIM_READY_NET_GUARD=on` 开启。**正式结果通过后已改为默认开启**，`off` 可独立回退。LLM 配置关闭，旧评估基线显式固定关闭。验证对照为本轮开始时的正式版：机会约束和副露投影均开启；两臂只差本开关。

## 预先固定的验证与决策

1. 原始两个案例只作诊断，不作为独立验收样本；检查新选择合法、视图未被修改。
2. 单元验证高风险的听牌晋升可以被拒绝，正向综合分的听牌晋升仍允许，默认回退和杠不变。
3. 试跑种子 1400001–1400004，仅验证接线、触发和耗时，不调参数。
4. 正式固定 **128 个未用种子**：1410001–1410064、1420001–1420064，各拆两个 32 种子分片。四座轮换、1 候选对 3 对照、四局东风场积分结转，共 512 场候选和 128 场全对照。
5. 主指标是每座每东风场配对净分；按来源种子聚类，4000 次 bootstrap。未改招的场次也纳入。
6. **只有合并 95% 区间下界 >0 且两批点估计均正，才启用默认调整。** 同时披露第一比例、大额付款和尾部损失。结果不明确或负向时保留默认硬优先，不能因为个案看起来更合理就改默认。按用户授权，达到标准后直接接入并回归、同步，无需再次确认。

不通过追加样本、换种子、重调权重去追求显著。全部本地计算，零付费 LLM 调用。

计算优化：本开关只被未锁手的弃牌响应吃／碰评估消费，因此其他窗口可直接复用对照的决策；新旧策略第一次分歧前也复用公共前缀。已用确实发生改招的种子 1400001 比较全算与优化，要求四座的整个东风场结果、每次改招、动作数全部相同。该优化不筛除任何场次，不改变算法或样本。

## 结果

**结论：本次最小调整达到预设标准，已直接默认启用。** 吃碰可以获得听牌奖励，但不能仅凭「从未听变听」就跳过综合分检查。保留所有其他排序和规则。

128 个正式种子全部完成：512 场候选东风场（2048 个候选完整小局），另有 128 场全对照（512 个控制小局）。统计单位为来源种子，不能把四个座位／四个小局当作独立样本。四片分别约 887／887／892／868 秒，并行约 15 分钟，零付费模型调用。

两批点估计均正，单批区间仍跨零；预先规定的合并主指标区间下界大于零，因此通过。合并标准误 46.70，正态近似区间 [+20.04,+203.10] 方向一致。折合每小局 +27.89，[+6.12,+52.32]。不得把它与先前不同样本的 +25／+50 分机械相加当作确定累计收益。

### 改招与代价

- 208/512 场发生分歧（40.6%），共 317 次改招：**碰→过 251 次、吃→过 66 次**。分析器检查没有混入其他类型变化。
- 完整场次净分：101 场更好、106 场更差、305 场相同（包括 1 场改招后净分相同）。**正向场次不是更多**，平均收益来自正向收益幅度大于反向损失，不能宣传成“多数场次都更强”。
- 来源种子均值：59 正、52 负、17 零。
- 第一比例差 −0.195 个百分点，[−1.563,+1.172]；平均名次差 +0.014，[−0.023,+0.047]。未证明夺冠或名次改善。
- 大额弃牌赔付（单批 ≥160 点）每场差 −1.86，[−6.99,+2.58]，未证明防守指标改善。
- 最大反向场次：`1420047 / 座位1` **−3700**，其次 `1420010 / 座位0` −3470；最大正向场次 `1410057 / 座位3` **+9190**，其次 `1420034 / 座位1` +8450。原始数据完整保留所有尾部结果。

### 正式调整与回退

普通血流 AI 默认开启 `BLOOD_FLOW_AI.claimReadyNetGuard`。单次决策传 `claimReadyNetGuard:false`，或设置 **`VITE_BLOOD_FLOW_CLAIM_READY_NET_GUARD=off` 后重新构建／重启开发服务**，可独立恢复硬优先，不影响已接入的 `routeOpportunityGuard` 和 `claimMeldProjection`。

正式对抗中两臂显式传 true／false，结论后只切换默认值，比较条件和权重未改。LLM 与 Python WS 策略不在此次默认推广范围；未验证半庄的牌力、人类或 LLM 对手，也不推断最优策略。半庄浏览器测试只证明流程正常。
