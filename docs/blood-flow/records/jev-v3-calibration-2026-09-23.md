# Jev 模板 v3 + 温度校正轮次记录（2026-09-23）

前置：`jev-cpu-pilot-2026-09-23.md`（v1 pilot 双臂拒绝）。本轮实施结案记录里的选项 1（校正飞轮第一轮：gold 采集 + 温度校正）与选项 2（模板 v2→v3）。协议与预算规则沿用 `docs/blood-flow/design/jev-selfplay.md` §4/§5。

## 一、本轮改动

### 1. 模板 v2：hint criteria 短语化（选项 2）

v1 直接复用 `candidateLine` 长特征行，1.5B 基座利用率极低（一致率仅比 blind +2.6pp）。v2 压成 `label·token` 紧凑格式，词表：`向N`（向听）`进M`（有效进张）`听K口` `安高/中/低` `险{档}{点数}` `得N`（胡即得）`链N`（锁手连锁）`门N`（首胡门槛）`改N[任]`（改张连锁）`抢N/过M`（抢杠两值）`发N`（过牌发育期望）`EV±N`（固定手毛收入）`杠净±N` `收{档}`。渲染器 `compactCandidateDescription`（`src/game/llm/jevBloodFlowInput.ts`），token 词表改动即升模板版本。

### 2. 模板 v3：claim 指令 bug 修复（质检发现的真实缺陷）

v2 gold 数据质检发现 `claim-window rows: 0`，但候选里有吃/碰（只存在于响应窗口）——追查出 `buildBloodFlowDecisionInput` 返回的 `request` 顶层**没有** `decision` 字段（真实来源是 `request.state.decision`，StateSnapshotV1），`buildJevBloodFlowRequest` 读错位置导致 **v1/v2 的所有响应窗口都错发出牌指令**（「轮到本家行动」）。单测夹具手写了该字段所以没拦住。修复：v3 以 `state.decision` 为唯一来源；自对弈冒烟新增**集成回归**（真实决策输入 → collect 的 claim 行必须带 claim 指令）。v2 采集数据作废（`train/dev.jsonl` 保留作 provenance，manifest 记录 templateId v2），`*-v3` 重采。

提交：v2+采集+校正工具 `a4bafdc`；v3 修复 `0d34e67`。

### 3. gold 采集与温度校正（选项 1，第一轮）

- 采集：`scripts/jev-selfplay-collect.test.ts`，四座全 EV（无 HTTP），与 pilot 请求**同源构造**。产物 `work/jev-calibration/train-v3.jsonl`（seeds 1000–1019，1821 行）与 `dev-v3.jsonl`（seeds 1020–1029，858 行），~91 样本/场，claim 行 372（20.4%）。gold=engineSuggestion（`BLOOD_FLOW_LLM_AI` 候选层）。
- 校正：`scripts/openjev-fit-calibration.py` 单遍评分（train 400 / dev 250 子采样，sample-seed 7，logprobs 断点缓存），黄金分割拟合 choice 温度，dev 在同一份缓存上出 T=1 与 T* 两组指标。不用 CLI `calibrate`+`eval`（需 3 遍评分，CPU 上每遍数小时）。
- 评分成本实测：~14s/行（bf16 CPU，与 serve 延迟同源），400+250 行 ≈ 2.5h。

**校正结果（metrics-v3.json，2026-09-23T13:10 完成，评分 ~14s/行 × 650 行 ≈ 2.5h）**：

- **T\* = 4.383**（choice 温度；原始分布严重过度自信，锐度需压 ~4.4 倍）
- dev（n=250，sample-seed 7）：

| 指标 | T=1（原始） | T=T*（校正后） |
|---|---:|---:|
| accuracy（EV-gold 对标） | 26.4% | 26.4%（不变，验证温度不改 argmax） |
| NLL | 2.4998 | **1.8665**（−25%） |
| ECE | 0.3122 | **0.1401**（−55%） |

- train（n=400，T* 下）：accuracy 27.75%、NLL 1.819、ECE 0.113 —— 与 dev 接近，单参数拟合无过拟合迹象。
- 解读：T=1 时模型对 ~26% 命中率的决策给出 40–50% 级别的置信；校正后分布与命中率对齐，**confidence 从"装饰"变成可用于路由/分析的信号**（如「校准置信低于阈值时交回 EV 策略」这类门控现在有意义了）。
- 产物：`work/jev-calibration/calibration-v3.json`（serve --calibration 直接可用）、`metrics-v3.json`、断点缓存 `cache-v3/`。

## 二、机制说明（防误读，先于结果写死）

**温度缩放不改变 argmax**：校正**不可能**改变任何决策与净分——pilot 的配对差变化全部来自 **v3 模板**（短语化 + claim 指令修复）；校正的作用只体现在记录概率的诚实度（dev NLL/ECE、digest 置信分桶、高置信分歧标记的精度）。因此本轮验收分两条线：

1. **决策质量线**（pilot 配对差，预注册标准 ≤−100 拒绝）：检验 v3 模板是否显著改善 Jev 的选择；
2. **概率质量线**（dev NLL/ECE T=1→T*）：检验校正是否让 confidence 可用于路由/分析。

**终判（按 §4 预注册标准）**：
- blind-v3：首批 −371 ≤ −100 → **拒绝**；
- hint-v3+校准：合并均值 −637 ≤ −100 且 CI 上界 < 0 → **拒绝**。预声明的「无论结果不再扩样」生效，本轮结案。

**首批「hint 接近打平」是小样本幸运段**：同一模型/模板/校准，3000–3009 段 −41、3010–3029 段 −935，相差 ~900 点/场——单场配对差 sd≈1414，N=10 时 se≈450，首批结果与合并终判并不矛盾（首批 CI 本来就宽）。**方法论教训（写死进协议）**：本玩法单局配对差方差极大，今后任何臂的单批 N 不得低于 30 对，或改用多局场（ROUNDS≥4）压方差；N=10 只允许用于冒烟/延迟探针，不允许用于结案。

**决策质量线结论**：1.5B zero-shot + 短语模板 + 温度校正后，选择质量仍显著低于本地 EV 基线（30 对 CI 支持）。防守细节（放炮、大额赔付标记减少）相对 v1 有改善迹象，但跨种子段不可精确归因（见第四节修订）。

**概率质量线结论（达成）**：T*=4.383 下 dev NLL −25%、ECE −55%、accuracy 不变——confidence 已成为诚实信号，可用于「低置信交回 EV」的门控设计与后续分析。

## 四、与 v1 pilot 对照（参考性，跨种子段不可精确归因）

可以说与不能说的：

- **可以说**：两代模板下 Jev 臂都触发拒绝线；v3 的放炮率与胡牌数在多个种子段上都好于 v1 的水平（防守/进攻细节有改善迹象）；温度校正只影响概率记录不影响这些行为指标。
- **不能说**：v3 相对 v1 的配对差"改善"了多少（−605→−637 合并后基本持平，首批 −41 是段间幸运）；claim 修复与短语化各自的贡献（未做拆分对照臂）。
- 归因边界：v3 相对 v1 = 短语化 criteria + claim 指令修复（会改决策）+ 温度校正（不改决策）。行为差异只来自前两者，量级不可分离。

## 五、边界与下一步

- 采集是 teacher-on-policy（EV 轨迹）：学生（Jev）访问的状态分布有偏移；温度是全局单参数影响有限，LoRA 阶段需 DAgger 式迭代补采。
- choice 温度对 blind/hint 两臂共用（按问题类型不按模板）：blind criteria 分布不同，属近似。
- dev 指标基于 250 样本子采样（sample-seed 7），ECE 分桶较粗。
- **拒绝已触发**（合并 30 对 CI [−1115,−132]）：1.5B zero-shot 的**选择质量瓶颈**成立（与概率校准无关——校准只救概率不救 argmax）。剩余实质路径按优先级：①**Jev 降级为信号源**（noul 危险度/校准置信融合进 EV 策略，CPU 可行，且本轮已证明 confidence 是诚实信号——下一轮首选）；②LoRA 微调（gold 管线已就绪，需 GPU）；③更大基座（需 GPU/云）。
- 本轮全部产物：`work/jev-calibration/`（train/dev v2+v3 数据、cache-v3、calibration-v3.json、metrics-v3.json）；`work/jev-selfplay/2026-09-23-05-11-50-cpu-pilot-v3/` 与 `2026-09-23-06-59-41-cpu-pilot-v3-ext/`（分析包+digest）。`work/` 不入库，本记录为入库摘要。
