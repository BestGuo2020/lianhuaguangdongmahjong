# 首胡机会保护：修复与验收（2026-09-22）

## 问题与结果

2c926534东二窗口63，千问可以打一万把自摸听口从5种扩大到34种，却选择鸡胡收30并锁手；东四窗口316/321，DeepSeek分别在墙5/4时因单次5分低于10分门槛反复过牌。本轮增加两个范围有限的本地策略保护，LLM配置winOpportunityGuards=true启用，可显式false回退；普通AI默认不启用。未改变计分、动作竞争规则、整套legacy估值或40/20/10基础门槛。

## 改张保护

只有同时满足以下条件，才在请求模型之前执行本地已推荐的弃牌，来源标local-strategy / verified-any-wait-reform：

- 本家未锁手，当前是本家摸牌且可胡；推荐为合法改张弃牌，不能只是摸切。
- 正常轮转估计至少还有两次本家摸牌机会。
- 公开信息的弃牌风险不高于基础未知风险档，不用仅有收入的估计覆盖明显放炮风险。
- 规范计分器逐一评估34种自摸牌：改张后均可胡，原锁手并非任意听；对于原来能胡的每种牌，改张后的单次自摸收入不降低。
- 用本家合法可见牌数估计同一时段固定手牌自摸收入，计入放弃的即时三家支付；扣除风险启发值后的改张估计至少为立即胡方案的1.2倍，并至少高10点。

因此不是任意听必改张，也不是强制跟随每个推荐。高额即时胡、昂贵弃牌、已经任意听、机会不足都不会触发。该估值采用未见牌可交换和正常轮转假设，不是保证未来收益；没有计入未来再改手或完整对手付款模型。

## 尾巡点炮保护

仅作用于当前合法选择只有胡/过、未锁手、来自别人弃牌的点炮窗口。墙数进入既有残局区间且正常轮转估计至多剩一次本家摸牌机会时，将该窗口的首胡门槛豁免为0。推荐因此不再被“5 < 10”单独压成过；LLM执行层直接采用胡，来源标local-strategy / last-ron-opportunity。

正常机会数按本家与弃牌者的位置计算，不是把“墙5”一律当一次机会。吃碰杠竞争、抢杠、自摸改张和已锁手分支不适用此豁免。其他座位竞争仍由权威引擎解算，提交胡不保证一定结算。吃碰杠也可能改变实际轮转，因此该机会数是明确标注的估计。

## 回归与实际执行

- 新增10项定向回归：原局模拟模型选择立即胡、两处尾巡重复拒胡；已任意听、高即时收入、危险幺九、机会不足、两次以上机会、竞争动作/抢杠/锁手、过期窗口、来源记录、历史回退等边界。
- 修复前，前三项分别得到win/pass/pass而失败；修复后得到打一万/win/win且来源正确。
- 真正模型请求不会在这三个保护窗口发生；没有虚构attempt，也不把本地保护算作模型成功回答。
- 在原局稳定窗口复制权威引擎，保留窗口开放时间，提交修正动作：东二63打一万被接受且不锁手；东四316和321的两个独立分叉都胡牌、锁手、实际收到5分，物理牌守恒通过。两分叉不是一条完整后续，不能合计成整场追回10分。
- 原始四局579条命令和181笔结算仍完整复现。正式夹具只含单座合法视角，不依赖Downloads文件。
- 提示词升级为v4，胡候选标floorWaived，并明确尾巡豁免及正常轮转假设。实际分析快照会保存winOpportunityGuards配置。
