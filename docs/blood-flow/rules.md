# 血流规则与体验约定

更新：2026-09-05；规则版本：`lotus-blood-flow-v1`。本文维护现行产品要求和规则默认值；实施状态只见[当前任务](tasks.md)，测试证据只见[验收记录](acceptance.md)。

## 范围与默认值

### 用户已明确的要求

- 只做前端单机和 P2P，不实现 Python 游戏后端、WebSocket 新玩法、新 TTS 后端或代理服务。
- 在现有莲花麻将基础上新增血流，增加下列 16 种常规番型；保留原特殊手。十三幺基础 16 倍，加入硬胡 ×2。
- 不增加双字顺、三字顺、四字顺、全顺、七字齐等新番型；现有字牌顺子仍是合法面子。
- 复用现有动作报声代码、音频资源及角色音色路由。不新增一套“我胡了”语音，不重写普通出牌 / 吃碰杠报声策略，不让同一动作重复播两次。
- 局内胡牌只有现有动作报声、番型、分数、特效和盖楼；首次胡、大番、多响、逆转均不触发感言或付款者反应。
- 全桌感言只在整局结束后启用，且仅限 `llm`、`llmAnime` 主题；其他三个主题无感言气泡、感言语音及相关 TTS 请求。
- “莲花”只表示地名与玩法来源；不派生花卉符号、地域风格或世界观。五主题沿用各自概念。

### 本版实施默认值

以下由前面的建议收敛成可编码的默认配置，不虚称用户已逐条确认；实现时集中配置，不分散写死。若用户调整，更新版本与测试预期，不另行猜测。

| 项目 | 本版默认 |
|---|---|
| 新规则键 / 显示名 | `lotus-blood-flow` / 莲花麻将·血流 |

| 底分 / 初始分 / 封顶 | 10 / 2000 / 每次胡牌每位付款人最终 64 倍 |
| 首胡后 | 固定暗手和副露，不再换张、吃碰杠；只处理新摸牌的胡 / 过 / 摸切 |
| 普通点炮 / 自摸 | 点炮者分别向赢家付款；自摸由另外三家付款，已胡玩家也付 |

“整局结束”指本局牌墙耗尽且最后响应完成，不是任何一家胡牌，也不是必须等整场 4 / 8 局全部结束。

### 现有行为需要保留

- 保留 136 张实体牌、两次骰子、双精和白板受限替代。当前前后端均移出整墩两张，实际发摸序列为 134 张；指示牌与底张分别参与守恒，底张不公开。
- 保留数牌吃、乱风吃、三元吃、普通杠与风杠。精牌打出或被抢时只按本张参与本次胡；对方暗手中原有精牌仍可替代。
- P2P 已有房主主题同步及客机主题锁定，本轮不新增混主题房间。感言使用本机已生效的房间主题判断，以防迟到事件；不另建主题同步机制。
- LLM 决策、普通动作音与感言是不同通道。关闭感言不得关闭 LLM 打牌或静音全部动作。

## 规则与计分规范

### 番型目录

除单独说明外，以下条件都在同一合法分解中判断，包含全部副露、将牌和本次胡牌张。普通同牌杠可以替代刻子；风杠不能替代同牌刻子。

| ID | 名称 | 基础倍数 | 判定 |
|---|---|---:|---|
| `pure-suit` | 清一色 | 4 | 恰好一种数牌花色，无字牌 |
| `mixed-suit` | 混一色 | 2 | 恰好一种数牌花色与字牌同时存在 |
| `all-triplets` | 碰碰胡 | 2 | 四副同牌刻 / 普通杠加将；无数牌顺、字牌顺、风杠 |
| `little-three-dragons` | 小三元 | 4 | 两种箭牌刻 / 普通杠，第三种箭牌作将 |
| `big-three-dragons` | 大三元 | 8 | 中发白三种各一副刻 / 普通杠 |
| `little-four-winds` | 小四喜 | 8 | 三种风刻 / 普通杠，第四种风牌作将 |
| `big-four-winds` | 大四喜 | 16 | 四种风牌各一副刻 / 普通杠 |
| `nine-gates` | 九莲宝灯 | 16 | 无任何吃碰杠；同花色 `1112345678999` 加同色任意一张，按最终牌形判定 |
| `all-green` | 绿一色 | 16 | 仅二三四六八条与发，组成合法和牌；不强制有发 |
| `pure-terminals` | 清幺九 | 16 | 仅数牌一九的四副刻 / 普通杠加将 |
| `mixed-terminals` | 混幺九 | 4 | 仅数牌一九与字牌的四副刻 / 普通杠加将，数牌和字牌均须有 |
| `three-concealed-triplets` | 三暗刻 | 4 | 至少三副暗刻 / 普通暗杠；其余面子可为顺子 |
| `four-concealed-triplets` | 四暗刻 | 8 | 四副暗刻 / 普通暗杠加将 |
| `all-honors` | 字一色 | 8 | 完整和牌全为字牌，允许现有字顺与风杠 |
| `three-kongs` | 三杠 | 8 | 至少三副已成功声明的四张同牌杠，另有合法面子和将 |
| `four-kongs` | 四杠 | 16 | 四副已成功声明的四张同牌杠加将 |

原特殊手：平胡 1、七对 2、十三烂 2、七星十三烂 4、十三幺 16。七对保持当前合法性口径，可叠牌种属性；十三烂、七星十三烂、十三幺作为独立特殊手，不追加面子 / 牌种番，但可按实际自然成立条件获得硬胡。

### 精牌与硬胡

- 可替代分解：精牌可代表任意牌；白板仅可代表本局精牌牌面或白板本身。已落地的吃碰杠不重新解释。
- 自然分解：完全按真实牌面成立，精牌与白板均不用替代能力，硬胡 ×2。物理上含精不等于一定软胡。
- 各分解分别完成番型组合、硬胡、自摸等事件与封顶后，取最高合法支付；同分优先自然分解，再按稳定番型 ID 顺序，确保两端显示稳定。
- 不能从分解 A 取得硬胡资格，再给分解 B 的替代高番 ×2。
- 外来精牌只消费该张牌的普通身份；不能将暗手中所有同种精牌一起降为普通牌。
- 虚拟代表牌不改变实体牌库数量。当前规则允许的绝张替代口径保留；不得在新评分器内顺手改变旧模式合法性。
- 每次血流胡牌都重算分解、硬胡与事件标记，不继承首胡标签。

### 明暗与杠的边界

- 点炮 / 抢杠牌补成刻子时，该刻不算暗刻；补将不影响另外四副暗刻。按本次胡牌张的合法归属分别评分。
- 普通暗杠算暗刻，碰、直杠、补杠不算；不能以 UI 是否亮牌判断明暗。
- 三杠 / 四杠只数已提交普通杠：风杠、手中四张未声明、pending 补杠、被抢的补杠均不计。碰升补杠仍是一副。
- 风杠仍占一个结构面子，有四张字牌实体和原有即时杠分，但不算暗刻、同牌刻或本轮三 / 四杠。

### 组合、事件与支付

排除关系：四暗刻包含三暗刻和碰碰胡；四杠包含三杠和碰碰胡；大四喜、清幺九、混幺九包含碰碰胡；九莲包含清一色。大小三元、大小四喜按定义互斥。小四喜和大三元不必全刻，因此实际满足时允许另计碰碰胡。

计算步骤：

1. 每个分解匹配番型，去除被包含项；`M = 1 + Σ(weight - 1)`。
2. 事件倍率 E：普通点炮 1，自摸 2，抢普通补杠 2，杠后自摸 4。它们按来源互斥分支取值，不重复贴自摸标签收三家钱。
3. 天胡 / 地胡默认与本次普通结果择高：该分解的事件后倍率 `Q = max(M × E, 8)`；非开局事件 `Q = M × E`。开局加成不另行连乘，首胡批次结束后关闭后续天胡 / 地胡窗口。
4. 该分解自然成立时 H=2，否则 H=1。单家支付 `10 × min(Q × H, 64)`。
5. 每位赢家选择合法最高支付；点炮 / 抢杠只向来源玩家收，自摸向另外三家收。多响统一提交聚合收付向量。
6. 即时杠分单独结算，不乘硬胡或重复胡次数：直杠来源付 B，补杠其他三家各付 B，暗杠 / 风杠其他三家各付 2B。

算术验收：硬胡十三幺点炮 320，自摸每家 640 / 总收 1920；硬胡清一色 + 碰碰胡自摸为 20 倍，每家 200 / 总收 600。已经封顶后不再额外翻倍。

## 胡牌后的续行与账本

| 本次事件 | 提交后 | 下一动作 |
|---|---|---|
| 自摸 | 本次摸牌归档，剩余暗手锁定 / 保持锁定 | 赢家下家摸牌 |
| 点炮多响 | 来源弃牌只归档一次，各赢家手牌不永久加牌 | 出牌者下家摸牌 |
| 抢补杠多响 | 原碰保留，第四张归档；不补牌、不收该次杠分 | 被抢者下家摸牌 |
| 普通弃牌无人胡 | 执行同一窗口已经收集的杠 / 碰 / 吃决定，不再要求先过再选 | 无人响应时出牌者下家摸牌 |
| 补杠无人抢 | 正式完成补杠并支付一次杠分 | 杠者从牌尾补牌 |
| 锁手后自摸过胡 | 仅能打出本次摸牌，其他人照常响应 | 正常弃牌流程 |
| 最后摸牌 / 弃牌 | 完成本次全部胡响应，无牌可补时禁止新杠；不再开无意义的吃碰循环 | 汇总并结算本局 |

- 天胡使用开局明确记录的第 14 张归档。末张多响提交完整批次后才汇总整局。
- 一张来源牌允许多个展示记录引用，实体账只归档一次；同一窗口同席最多提交一次决定。
- 每次支付四家变化总和为零，局末净分等于所有已提交胡 / 杠账本项，不重放历史扣分。
- 136 张实体包括翻精两张、牌墙、暗手、副露、弃牌及胡牌归档；有效手牌结构按暗手加 3 × 结构面子数判断，杠的额外实体单列。
- 局内胡牌不触发旧终局时间线、全桌亮牌或完成场次计数。动画和声音不提交积分、锁手或摸牌。

## 通用交互必须保持一致

- 摸打、吃碰杠、选牌、手牌间隙、倒数提醒、听牌提示和结算按钮复用既有交互契约。新引擎需要适配，不构成改掉原体验的理由。
- 待出牌时的 14 / 11 / 8 / 5 / 2 张手牌，间隙沿用原版；有明确摸牌标记时本次摸牌保留在最右端，不能在排序后的中间开缝。
- 能胡又能碰 / 杠 / 吃时直接显示并选择，不先要求点过；一次过牌跳过该窗口的全部候选，实际执行仍由权威裁决。
- 保留“当前听口、打哪张可听、选中牌打出后的听口”三类提示；增加血流番数不删原提示。
- × 和查看牌桌收起结算，桌面有返回结算；同局重复快照不重弹。末局先展示最终排名，可主动查看最后一局结果。

## 局内信息层级

本轮展示目标如下；保留全部计分事实与可查询明细，调整默认展示位置、时机和重复内容。改动限定血流的默认信息展示，共用组件通过既有可选能力适配，保留非血流的布局和操作行为。

| 层级 | 默认显示 | 按需查看 / 退出当前层 |
|---|---|---|
| 日常牌桌 | 手牌、副露、牌河、当前行动者、头像与积分、头像旁胡次数、精牌图标、必要局况 | 二骰结果、白板替代长说明、完整规则进入对应详情；不重复显示独立层数标签 |
| 待操作 | 本次全部合法的吃 / 碰 / 杠 / 胡 / 过；可胡时一份简洁预览 | 预览明确是“预计”收益；完整牌型与支付说明点击查看。首次可胡保留锁手后果的简短提示，锁手后用短状态标识 |
| 听牌查询 | 保留现有牌面＋预估倍数＋余张网格，按用户点击或选牌交互显示 | 不恢复逐牌自摸 / 点炮金额的价目表；不能因同窗快照刷新打开一份已收起的说明。当前听口与选牌后听口语义继续区分 |
| 胡牌与收付 | 先动作 / 角色，再逐席主番；收付阶段每席只显示一次正负金额，多笔合并才标“合计” | 不重复主番、倍率、胡牌方式和修饰，不再显示赢家摘要卡或底框。完整番型、倍率和来源留在流水；名称通过头像、位置和无障碍标签表达 |
| 流水与结算详情 | 用户主动打开后显示完整信息 | 全部计分番型、排除项、来源玩家、支付关系、逐笔胡杠明细留在这里，不因为减密度丢失数据 |

- “中番 / 大番 / 顶级番型”“某某 · 本次变化”“三家付款”等泛化说明不在每次演出里反复出现。等级由演出层次表达，收付关系结合来源强调与对应席位数字表达。
- 一次事件的“预计收益”与已经发生的收付必须区分。合法操作开放后，旧事件退到席位反馈，不能让旧结果卡与新预览占同一主要阅读区域。
- 主标题、角色亮相、详细提示不同时占据主舞台。多响允许赢家分席位同阶段出现，共享提示和角色 / 牌型阶段错开。
- 示例：动作与主番展示完成后，赢家只显示 `+600`，三位付款者各显示一次 `-200`；“清一色·碰碰胡 / 20倍 · 硬胡 · 自摸”可在流水查询。这是底分 10 的已有规则算例，不引入新计分。
- 合法动作按钮、来源牌、持续盖楼、光柱、粒子及原动作报声继续保留。信息减负优先减少解释性文字和重复金额，不通过删正常操作或削弱基础反馈实现。

## 演出、声音和发言

- 来源与动作确认 → 主番重拍和楼位强调 → 稳定读番 → 四家收付 → 交回操作。字、牌、光、数字和 llmAnime 获胜角色立绘共享同一批次时钟；角色和主字按阶段交接，再调整光效层次。
- 五个主题的胡牌光束、光晕、星芒和粒子沿用对应非血流版本的原有效果，不再套血流专属颜色、宽高或强度覆盖。光效仍落在本次赢家楼位并消费共享时钟；减少动态效果设置保持有效。
- 实现或重新设计特效前，必须实际查看用户指定的[优先参考视频](references/impact-video.md)，按演出细则核对自摸、放枪、多响及字效片段。只读文字分析不替代看画面；参考里的牌规、金额、角色资产和直播覆盖物不移植。
- 胡牌楼持续向上增长，桌面每层 4 张、小屏每层 3 张；不恢复旧三层 / 两层上限或超过 12 张转收纳。展示记录引用不增加实体牌数，重连直接恢复楼层。
- 演出只展示真实番型、最终倍率和收付；本次胡牌结果与下一次可操作预览必须分清，不能在中心和操作区同时堆两个未说明所属事件的番数。大字须避开桌心方位 / 倒数；楼的落点与四家收付可辨。
- 五主题各用自身视觉概念；不由地名、九莲宝灯等牌型名称衍生项目级花卉装饰。桌布人物不当成获胜玩家立绘。
- 原动作人声使用现有资源、固定角色 TTS 或原配置路由；配置 LLM 不自动意味着所有声音都走新 TTS。另接已有非人声 `hu_effect_sound.mp3` 对齐重拍，不能取代或重复人声。
- 普通动作气泡只在 llm / llmAnime、启用相应模型时按既有性格和频率策略显示。摸牌不为聊天额外请求一次模型；吃碰杠短句须在动作实际执行后展示，被胡截断的碰不能先说已碰。
- 局内胡牌不生成赢家感言、付款者反应或自由评价。原“胡 / 自摸”等简短报声保留；全桌感言只在本局结束后、仅两个 LLM 主题出现。
- 局末文字显示在对应结算玩家卡；回桌可展示同一句，重新打开不再次生成 / 播放。换局、离场或主题变化取消过期感言，静音和 TTS 失败不锁住按钮。
- 静态截图只证明某一帧的外观；过冲、命中、飞行、收付时序及实听需要带音轨录像。参数和自动化通过不等于用户已认可打击感。
