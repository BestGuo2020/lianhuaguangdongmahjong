# 血流本地 AI 贪婪 EV 策略（2026-09-07 定稿）

## 番值表重平衡（2026-09-12，参照广东麻将番型表）

**起因（实测）**：20 局 727 次胡牌里，4 番档 95% 集中在「七星十三烂 + 三暗刻」，8 番档只有四暗刻 3 次，**清一色与七对因权重过低（4 / 2）一次都没做成**——大牌番过于集中。参照[广东麻将番型表](https://doublewin.me/guides/mahjong-gd)（大三元/大四喜/十三幺 88、字一色/清幺九 64、小四喜/小三元 48、豪华七对/混幺九 32、清一色/七小对 16、混一色/碰碰和 8、鸡胡 2）把相对比例拉开，并新增**豪华七对**（七对含自然四张相同）。

**同步上调封顶**：单家封顶 64 → **128**。否则顶端会被吃掉——十三幺 16 番硬胡自摸 = 16×2×2 = 64 正好撞顶，提到 32 番也毫无变化。

| 番型 | 旧 | 新 | 番型 | 旧 | 新 |
|---|---:|---:|---|---:|---:|
| 大三元 / 大四喜 / 十三幺 / 九莲 / 四杠 | 8 / 16 / 16 / 16 / 16 | **32** | 混幺九 / 三杠 | 4 / 8 | **12** |
| 字一色 / 清幺九 / 绿一色 | 8 / 16 / 16 | **24** | 清一色 | 4 | **8** |
| 小三元 / 小四喜 / 四暗刻 | 4 / 8 / 8 | **16** | 七对 | 2 | **6** |
| **豪华七对（新增）** | — | **16** | 三暗刻 / 七星十三烂 | 4 / 4 | **6** |
| 混一色 / 碰碰胡 | 2 / 2 | **4** | 十三烂 / 平胡 | 2 / 1 | 2 / 1 |

**实测对照（20 局固定种子，普通 AI）**：

| 番型 | 改前 | 改后 | 番型 | 改前 | 改后 |
|---|---:|---:|---|---:|---:|
| 平胡 | 399 | 414 | 四暗刻 | 3 | 2（**255 点/付**） |
| 七对 | 213（每付 28 点） | 142（**每付 80 点**） | **豪华七对** | — | **1（硬胡，640 点）** |
| 混一色 | 44 | **70** | 清一色 | 0 | **仍 0** |
| 三暗刻 | 13 | **30** | 总胡次数 | 727 | 688（−5%） |
| 七星十三烂 | 40 | 29 | 按最高番分布 | 1番 55% / 2番 37% / 4番 7% / 16番 0.4% | 1番 60% / 2番 2.5% / 4番 7.7% / **6番 29.2%** / 16番 0.4% |

**结论与边界**：

- 重平衡让"中高番"成为真目标（6 番档从 0 变成占 29%），收益结构里中高番占比从 ~33% 升到 ~45%，总胡次数仅 −5%。
- **加权重不会提高频次**：清一色仍然 0 次，混幺九 / 三杠 / 大三元 / 字一色 / 清幺九 / 绿一色 / 九莲也仍是 0——这些牌型需要**结构性承诺**（弃两门 / 全字牌 / 三个杠），纯权重调不动 AI 的期望值模型。要让它们出现，得用 v4 那种"引擎定方向 + 候选收窄"，或者改规则（不能吃、承包等）。
- **前后端同源**：后端 `app/core/blood_flow/{config,catalog}.py` 为同一份表（含豪华七对与封顶 128）；跨语言逐位对拍基线 `work/blood-flow-pair-inputs.json`（本机文件，`work/` 被 gitignore）已按新表重放刷新。
- 参考表还有两条我们**尚未实现**的机制：**承包**（碰两组成员后放第三组 → 一人付三家）与**海底捞月/杠上炮**事件番——它们比拼权重更能改变"做大牌"的收益结构。


范围：master 前端本地 AI（非 LLM 主题座位与 LLM 回退路径）。LLM 决策提示词、计分、封顶、锁手、胡后自动续行规则一律不动；P2P / vibehub 原为后置项，**2026-09-10 已上线验收**（联机模型原话与 TTS 由服务端/宿主下发，本地 EV 策略继续作为补位与回退路径）。策略只做决策，不改任何规则状态。

## 决策框架

同一响应窗口内的可选动作全部折算成期望收益（EV），取最大者。胡不再无条件优先（多响裁决时"胡优先"是规则层的事，与 AI 自己的选择无关）。锁手后行为不变：有胡就胡、没胡摸打、窗口自动过。

### 单次胡收益（实际窗口用引擎精确分）

- `立即收益 = paymentPerPayer × 付款人数`（自摸/杠后自摸 3 家，点炮/抢杠 1 家）；`paymentPerPayer` 直接用引擎给该窗口算好的 `ownScore`，不自算。
- 封顶、硬胡、事件倍率都在引擎分里，AI 不再另算。

### 连锁期望（锁手后继续胡）

锁手后手牌冻结，后续期望只取决于听口宽度与剩余牌：

```
chainEv(hand13, melds) =
  Σ_{t ∈ waitingTiles(hand13, melds, jokers)}
      remaining(t) × avgWin(t) × chainFactor

avgWin(t) = (selfDrawWeight × 3 × paySelfEst(t) + 1 × payDiscEst(t)) / (selfDrawWeight + 1)
chainFactor = min(1, chainHorizon / max(1, wallCount / 4))
```

- `paySelfEst / payDiscEst` 用廉价估算器 `estimateWinIncome(hand13 + t, …)`：番型权重叠加 × 事件倍率 × 硬胡近似（手牌无精牌才计 ×2）× 每人封顶 64，只用于排序，不用来结算。
- 单吊任意听（`waitingTiles` 返回全部 34 种）时 chainEv 自然爆表——这就是"改张为单吊任意听"的量化依据，不需要特判。

### 首胡门槛（拒绝"见胡就胡"的快路径）

首胡锁手的代价最大。当本次支付低于当前阶段门槛、且手牌改造潜力达到 `potentialFloor` 时，拒绝本次胡（选择过 / 改张 / 其他动作），保留发育权：

| 阶段（墙余 wallCount） | 门槛（单家支付，取合法 10 的倍数档） |
|---|---|
| 早局 > 40 | 40 |
| 中局 16～40 | 20 |
| 残局 ≤ 15 | 10（= 见胡就胡，先解锁连胡资格） |

潜力不足（烂牌）时门槛不生效，见胡就胡。

### 改张（自摸窗口）

摸牌能胡时，枚举全部合法弃牌 `i ≠ 摸牌位`，计算弃后 13 张的 `chainEv + 潜力分`；存在 `改张EV ≥ 1.2 × (立即收益 + 锁手 chainEv)` 时，选改张（弃别的牌保留摸牌），否则按上面门槛决定胡或过。锁手后不适用（自动摸打）。

### 抢杠窗口（用户定稿：同样贪婪比较）

选项只有胡 / 过：

- `EV(胡) = 抢杠单家支付 + 锁手 chainEv(当前 13 张)`
- `EV(过) = −补杠杠分 + 继续发育期望（潜力分 + 已听时的 chainEv）`

贪婪取大。多数局面胡仍占优（被抢牌绝张、白付杠分、事件 ×2），但低番抢杠 vs 距任意听 / 大番只差一张时会过。锁手后不变（自动胡）。

### 吃碰杠与弃牌

- 保留 lotusAi 现有 decideTurn / decideClaim 的听口、向听、安全度框架（经典玩法零改动）。
- 血流调用时注入四个可选回调节点（默认不传，经典行为不变）：
  - `patternBonus`：番型潜力分（见下）加权进候选弃牌/碰吃质量；
  - `safetyExposure`：放炮成本 = 牌河公开张数档位（0 → 0.25 / 1 张 → 0.1 / ≥2 张 → 0）× 估算单家支付 × **对手牌型风险档**（见下节），从候选弃牌 EV 里扣除；
  - `opponentRisk`（2026-09-10 追加）：对手牌型风险档的三元组（tier / 倍率 / 信号），供候选特征与 prompt 复用；
  - `kongEvaluator`（2026-09-13 追加，用户定案第 3 步）：开杠候选的净值 `杠收益 − 防守风险 − 自手牌型损失`，见下节。

### 开杠价值（2026-09-13 追加，用户定案第 3 步）

问题：改动前 `decideClaim` 是 `if (canGang) return { kind: 'gang' }`，`decideTurn` 的暗杠/风杠/补杠只看"是否已听牌"。于是"手上三张 + 别人打出第四张"这类**正在走七对 / 豪华七对路线**的牌会被无条件拆成副露——路线一旦副露就永远不可能，豪华七对在开杠实验臂里 0 次就是这么来的。

规则（`bloodFlow/kongValue.ts`，纯函数；**不是**"检测到七对就禁杠"）：

```
开杠价值 = 杠收益 − 防守风险 − 自手牌型损失        （单位：点，与其它 EV 同口径）

杠收益   = 底分 × kongPayments[kind] × 付款家数（明杠 1 家 / 其余 3 家）
         + 底分 × kongBonus[kind] × bonusWeight（倍率加成，默认按单家一份折算）
防守风险 = 仅补杠：抢杠风险（未见张 100% / 见 1 张 35% / ≥2 张 15% × robRisk=60 点）
自手牌型损失 =
   ① 七对 / 豪华七对潜力损失 = (路线价值(杠前) − 路线价值(杠后)) × 底分
      路线价值 = Σ 番值 × 接近度²（七对 4、豪华七对 6；接近度 = 对子数/7，
      豪华再加"已有刻子/四张或精牌可补成四张"的四张进度）；任何副露 → 路线价值 0
   ② 明杠破坏门清平胡 = 2 番 × 底分 × 门清平胡接近度 × concealedHandFallback(0.5)
      （门清平胡是**兜底本体**，只有别的番种都不成立时才兑现，因此折价；已有副露时为 0）
   ③ 向听恶化 = max(0, 杠后向听 − 杠前向听) × shantenStepLoss(10 点)
      （含七对/十三幺/十三烂的"整车"向听；杠后必然有副露，特殊路线随之消失）
```

决策：`net = 杠收益 − 防守风险 − 自手牌型损失`，**净值为正才压过"不杠"**（保留手牌照常打牌），明杠/补杠/暗杠/风杠共用同一把尺子；`BLOOD_FLOW_AI.kongValue.mode = 'off'` 一键回退到旧口径做 A/B。要点：

- **路线没成形就不扣**：对子不足（`sevenPairsPotential = 0`）时 ① 为 0，该杠照杠；损失随接近度连续变化，不是开关。
- **只有杠候选受这条约束**：碰/吃的候选质量比较（`compareQuality`）不变；明杠窗口里"碰"本来就被 `dropDominatedPeng` 撤掉，所以不杠 = 过。
- **自摸胡不再被杠候选顶掉**（kong-priority 臂的关键修复）：`applyActionPriority` 原来只要存在杠/碰/吃候选就撤掉"胡"候选。手上四张（豪华七对成立）时**必然**存在暗杠候选 → 胡候选被撤 → AI 打掉胡牌张。现在撤胡之前先算 `kongsOutweighWin`：最优杠候选的净值必须超过胡的即时收 + 连锁期望才会压胡，否则保留胡候选。
- **门槛与口径**：杠收益按"即时杠分 + 一份倍率加成"计，不做胡牌概率折现；抢杠风险按公开张数分档（与旧 `shouldTakeAddedKong` 的档位一致）；门清平胡按兜底折价。四项常数都在 `BLOOD_FLOW_KONG_VALUE` 里，可单独调。
- **后端镜像（WS 联机的机器人走这份）**：`backend/app/core/blood_flow/kong_value.py`（同公式同常数）+ `config.py` 的 `KongValueConfig` + `lotus_ai.py` 的 `_accepts_kong` 钩子 + `blood_flow/ai.py` 注入 `kongEvaluator`；`backend/tests/test_blood_flow_kong_value.py` 与 `backend/tests/test_blood_flow_seven_pairs_model.py` 里有**跨语言数值护栏**，前端同一组数字在 `src/game/variants/lotus/bloodFlow/crossLanguageNumbers.test.ts`（**两侧数字必须同时更新**，2026-09-18 番值改动时只改了前端一侧，后端镜像静默失效 9 例）：收益 20/40/80/70、七对损失 31.43/100.0、门清听牌 5.0、净值 −24.43/−30.0（见下表）。注意后端**没有** kong-priority 开关，所以"撤胡候选"那条修复在后端不适用（那边本来就不会撤胡）。
- **LLM 接线**：杠候选新增 `features.kongValue{gain,risk,selfLoss{total,sevenPairs,concealedHand,shanten},net,reasons}`（前后端同源，规则摘要逐字一致由 `backend/tests/test_blood_flow_llm.py::test_prompt_rules_mirror_frontend_literal` 守着），候选摘要渲染 `开杠价值：-24（收益20−风险0−自损44）｜开杠代价：拆掉七对/豪华七对路线（-31）、破坏门清（-3）、向听恶化 1 档（-10）`；规则摘要补一句"net ≤ 0 表示这一杠会拆掉自己的七对/豪华七对、破坏门清平胡或让向听变差，默认建议不会是杠"。

### 七对潜力模型 v2（2026-09-13 追加，用户指正后定案）

问题（用户 2026-09-13 指正）：我先把豪华七对说成"5 对 + 刻子只能等第四张（窄听口）"。**精牌能替补第四张**，所以豪华七对不必等实体第四张；引擎逐张枚举 34 种听口证实：刻子+5 对（0 精）听 2 种、刻子+3 对+2 精听 8 种（4 种豪华）、**5 对 + 3 精 34 种全听**（29 种豪华 + 5 种断幺九+四暗刻）。而旧潜力模型 `pairs + min(singles, jokers)` 会**丢掉多余精牌**：H1/H2/H3/H5/H6 五手牌拿到完全相同的 29.4 点估值（都是"4 番 × 86%"），真实赔付差 3 倍；最狠的是 H4（全听）拿到**最低**的 20.4 点。

改动（`patternPotentials.ts` + 后端同源镜像，开关 `BLOOD_FLOW_AI.sevenPairsModel = 'ev' | 'off'`）：

- `sevenPairsAccount` 对齐引擎 `isSevenPairs` 的记账：c=3 → 1 对 + 1 单；精牌先补单张，**剩余精牌两两成对** → 有效对子 = `pairs + min(singles, jokers) + ⌊余精/2⌋`；
- `quadAvailability`（四张可达性）：`count + 精 ≥ 4 → 1`（实体四张 / 刻子+精 / 对子+2 精 / 单张+3 精）、`count ≥ 3 → 0.6`、`count + 精 = 3 → 0.5`、`count = 2 → 0.2`；用**手上全部精牌**估四张（引擎拆解穷举，先扣单张会把整条豪华路线吃掉）；
- `luxurySevenPairsProgress = 七对进度 × 四张可达性`，`'ev'` 下在 `sevenPairs`（4 番）之外**新增 `luxury-seven-pairs`（12 番）方向**；`certainPatterns`（连锁期望/改张 EV）同样认得它；
- `'off'` 逐位保持旧口径；经典玩法继续用旧 `sevenPairsPotential`，行为不变。

效果（种子 1–800、各 800 局同种子 A/B，详见 [记录：七对潜力模型 v2](../records/seven-pairs-model.md)）：豪华七对 **+9.7%**（1684→1847）、七对路线占胡牌 24.9%→**27.4%**、七对类番值份额 56.6%→**59.9%**；代价是胡牌率 **−1.6%**（38.37→37.75 胡/局），但**每局赔付 +1.0%**（1621.7→1637.8 点）、每胡赔付 +2.6%——即"少胡一点、胡得更大"，净值小幅为正。决策级：路线活时留对子 50.1%→52.5%、拆对 4.9%→4.2%、听牌可胡时拒胡 5.9%→7.3%（开杠臂 8.0%→11.2%）。

顺带修掉一处**既有镜像偏差**（新加的跨语言数值护栏抓到的）：Python 的绿一色分支要求"整手已经全绿"，前端只看副露 + 手牌算接近度（那是判定 vs 潜力方向的区别）。修完后 H1–H6 六手的潜力合计与豪华七对进度前后端逐位一致。

## 大牌路线收窄推广到普通 AI 座（2026-09-14 追加，用户定案）

v4 的大牌路线原本只覆盖十三幺/九莲、且只作用于 LLM 候选。用户要求推广到**普通 AI 座**并加三条"半大牌"线，同时划了一条边界：

> "如果起手特别好、可以做大牌的时候，是否会放弃？因为即使大牌不是任意听，胡几张收益非常之高，至少比鸡胡盖楼强。"

实现（`bigHandRoute.ts`，路线表 + 判定 + 收窄是**同一份**，LLM 与本地 AI 共用）：

| 路线 | 权重 | 成立门槛 | 副露策略 |
|---|---:|---|---|
| 十三幺 / 九莲宝灯 | 16 / 32 | 不变（门清） | 一律撤副露 |
| 清一色 `pureSuit` | 8 | 同色 ≥10 张（含精）且 异色+字牌 ≤2 | 只允许**同色**吃/碰/杠 |
| 混一色 `mixedSuit` | 4 | 同色 ≥10 且 另一门数牌 ≤1 | 同色或**字牌**吃/碰/杠 |
| 碰碰胡 `allTriplets` | 4 | 有效刻子 ≥2（精可顶对子）且 对/刻+精 ≥4，且无吃 | 允许碰/杠，**禁止吃** |

- 收窄是**路线感知**的：早期版本"一律撤副露"只适合门清路线，碰碰胡要靠碰、清一色允许同色吃。
- 多条同时成立时取 **番值 × 接近度²** 最大者（只比 progress 会让"11 张一门 + 2 字牌"选到低番的混一色）。
- 承诺门槛不变（`routePayoff ≥ 立即胡 × 2`）：**能胡成的大牌不会被放弃**——实测承诺状态下"保留胡"是"放弃小胡"的 4.9 倍。
- 开关：`BLOOD_FLOW_AI.bigHandRoute = BLOOD_FLOW_BIG_HAND_ROUTE_WIDE`（`mode:'bot'`，五条线）；`BLOOD_FLOW_LLM_AI` 同一路线表 + `mode:'llm'`。一行指回 `BLOOD_FLOW_BIG_HAND_ROUTE` 即可完全关闭。

实测（种子 1–600、各 600 局，详见 [记录：大牌路线推广](../records/big-hand-routes-bot.md)）：**每局赔付 +4.6%、每胡赔付 +19%、胡牌率 −12.0%**；清一色 21→51、十三幺 0→25、九莲 0→10、大三元 0→5、三杠 1→4、12 番档 6.0%→8.6%、24/32 番档从 0 到 14 次；代价是碰碰胡占承诺 81%（禁止吃 → 顺子路线被挤，清龙 1.05%→0.82%）。用户口径下选择"收益优先"，故按 wide 落地；保守档（去掉碰碰胡）在种子 1–200 上是 +2.1% 赔付 / −2.7% 和牌率。

**尚未镜像到后端**：`backend/` 目前没有路线判定/收窄的 Python 实现（v4 起就只在 LLM 候选构造里有），因此 **WS 联机的机器人**仍按旧口径打；vibehub（P2P）与单机走浏览器引擎，本次改动即时生效。

## 对手牌型风险定价（2026-09-10 追加）

问题：改动前 `safetyExposure` 只跟"该牌公开张数"有关，最高 10 点，而真实点炮赔付是 `底分 10 × 番型倍率 × 事件倍率`、单家封顶 64 倍——清一色硬胡点炮 80 点、十六倍级（十三幺 / 大四喜 / 九莲 / 四暗刻 / 绿一色 / 清幺九 / 四杠）硬胡点炮 320 点。也就是说"点炮给平胡"和"点炮给大牌"在旧模型里同价，AI 会为了多一个听口（`waits × 10`）去打生张。

新模块 `shared/ai/opponentPatternRisk.ts`（纯函数，**前后端同源**，Python 镜像 `backend/app/core/opponent_pattern_risk.py`）只吃公共牌：对手牌河、副露明细、已胡次数 / 锁手、墙余、公开牌池。**不接收也不推断对手暗手**（非本家 `hand` 为空时结果不变，有测试断言）。

档位（tier 取各项信号的最大值，倍率用于乘在公开张数档位上）：

| 信号（全部来自公共牌） | tier | 倍率 |
|---|---|---|
| 无信号 | 0 | ×1（= 旧口径） |
| 副露半染手（≥2 组且同花色占比 ≥0.5）/ 副露少牌河快听 / 残局少牌河 / 门清「牌河中张密集」（七对弱信号）/ 门清「牌河少打某花色」（短牌河 8～11 张里该花色 ≤1 张，兜底不丢灵敏度） | 1 | ×4 |
| 副露染手嫌疑（≥2 组且同花色占比 ≥0.75）/ 副露 ≥3 组 / 箭牌或风牌成组 ≥2 / 已锁手且已胡过 / 门清「牌河无字牌幺九」（十三幺·字一色）/ 门清「牌河几乎未打某花色」（九莲·清一色） | 2 | ×16 |
| 三组箭牌 / 三组风牌（三元、四喜系）/ 门清「牌河零字牌幺九」（牌河 ≥10 张）/ 门清「某花色一张没打」（牌河 ≥12 张） | 3 | ×32 |

门清大牌读牌（v2，2026-09-12 追加；这是 tier3 的主要来源）：门清对手没有副露，只能读牌河指纹——

- **字牌/幺九回避**：牌河 ≥8 张却几乎不打字牌与幺九 → 十三幺 / 字一色 / 混清幺九嫌疑（`honorTerminals <= 1` → tier2；为 0 且牌河 ≥10 → tier3）。
- **花色回避**：牌河 ≥8 张而某花色占比 ≤10% → 九莲 / 门清清一色嫌疑（tier2）；该花色一张没打且牌河 ≥12 → tier3。
- **中张密集**：牌河 ≥8 张且中张占比 ≥75% → 七对嫌疑（弱信号 tier1）。

逐张危险轴（**损失最小化的核心**）：同一个嫌疑不是"整手牌都贵"，而是按该牌型真正需要的牌分价——

```
exposure(tile) = 40 × ladder(公开张数) × max_对手( 倍率(tier) × 花色系数 × 中张系数 )
花色系数：染手嫌疑花色 1.0 / 非嫌疑花色 0.5
中张系数：十三幺·字一色嫌疑下，中张（2-8 数牌）0.25 —— 但嫌疑花色内的中张不打折（九莲要同花色 1-9）
公开张数下限：十三幺·字一色轴上的字牌与幺九，ladder 不得低于 0.1
  —— 该牌型每种只需要一张，"我手里有两张"只是降低概率，不等于安全（多现 ≠ 安全）
已锁手且已胡过的家：ladder 固定 0.25、花色与中张折扣一律取消（可能停在单吊任意听）
```

由此得到的"必打一张时选谁"的效果（永久断言见 `opponentRiskChoice.test.ts`）：对门清十三幺嫌疑对手，旧口径会先打孤张幺九，档位版改打中张（40 × 32 × 0.25 × 0.25 = 80 点）而不是送出活字牌（320 点）——这就是损失最小化：不是不点炮，而是尽量点小的。

- **等价性**：`BLOOD_FLOW_AI.opponentPatternRisk = 'off'` 或全部 tier=0 时，权重恒为 1，公式退化为 `40 × ladder`，与改动前逐位一致（有回归测试）。注意 `opponentPatternRisk` 是 `config.ts` 里的**常量级回退开关**（与其他血流 AI 参数同款），不是运行时 UI 开关：改 `BLOOD_FLOW_AI.opponentPatternRisk = 'off'` 后两侧（引擎建议与 LLM 候选特征）同时回到旧口径，需要重新构建前端。
- **广麻（无普通点炮）**：同一模块只用于补杠 gate —— 残局（墙余 ≤16）+ 该牌在公共牌池完全未现 + 对手最高档 ≥1 时放弃补杠（抢杠胡事件倍率 ×2）。候选风险文案同步升级为"对手疑似大牌，抢杠赔付远高于平胡"。
- **LLM 接线**：候选特征新增 `opponentRisk {tier, payment, signals}`（仅弃牌候选、仅非广麻；无信号时不出现该字段），候选摘要渲染 `｜风险赔付：约N点（档·信号）`；局面增加 `opponentRisk` 数组；`BLOOD_FLOW_PROMPT_RULES` 补上赔付口径与"8~32 倍"的对比。条件深思的 `estimateOpponentThreat` 改为消费同一份估算（tier3=90 / tier2=70 / tier1=40，墙余 ≤24 再 +10），消除"两套威胁估算"。
- **局限（已知并接受）**：读牌永远是概率性的——对手牌河不打字牌幺九也可能只是摸不到/碰巧不需要；门清大牌现在能读到 tier2/3，但"读到"不等于"防得住"（比如手上全是危险张时必须打一张）；锁手家的听口宽度仍无法区分（任意听与非任意听同价）；七对只有弱信号（牌河中张密集），四暗刻/字一色依赖字牌回避轴。这些都写在本节与 `opponentPatternRisk.ts` 注释里，不假装解决。

## 真·大牌路线（v4，2026-09-12 追加）：把"要不要做十三幺/九莲"从模型手里拿回引擎

**起因（实测）**：普通 AI 12 局 418 次胡牌里十三幺/九莲/**清一色都是 0**——不是随机，是结构原因：番型潜力在 EV 里权重小（十三幺 40% 接近度只值 25.6 点）、决策无跨轮记忆、`reformGainRatio 1.2` 门槛偏高；九莲更惨——`patternPotentials` 的 `suitCounts` 把**字牌也算一门**，只要手上还有一张字牌，九莲潜力就被乘 0 直接过滤掉（可修的小 bug）。

**LLM 侧的实测（走游戏客户端、`createBloodFlowDecisions`）**：同一手"13 种幺九 + 闲牌 + 有小胡"，`deepseek-v4-pro` 会放弃小胡去做十三幺，而 `glm-5.3` / `glm-5.3-flash` / `gpt-5.6-luna` / `gpt-5.6-sol` **全部选择直接胡**——**换更高档的模型也不会做大牌，越稳的模型越贴引擎期望值**。所以大牌路线不能靠提示词劝说。

**做法（v4）**：引擎判定路线已成立时，在 **LLM 候选层收窄**，模型只决定"怎么打"，不决定"做不做"：

| 环节 | 规则 |
|---|---|
| 路线判定（硬条件） | 十三幺：门清且已持 ≥12 种幺九字牌；九莲：门清且某一门凑齐 1-9 且该门 ≥12 张（字牌/别门牌不影响判定，它们本来就该打掉） |
| 时机门槛 | 牌墙 ≥20 张（还有摸牌余地）**或**落后 ≥300 分（需要大牌翻盘）才承诺 |
| 收窄 | 撤掉"胡"（当路线完成收益 320 点 ≥ 立即胡 × 2 时）、撤掉吃碰杠（会破坏门清路线）、弃牌只留"打出去后路线接近度不下降"的牌 |
| prompt | 增加 `bigHandRoute{label,progress,need,committed}` 与 commitment 说明（补上跨轮记忆） |
| 生效范围 | **只作用于 LLM 座位**（`BLOOD_FLOW_LLM_AI`）；普通 AI 座位走 `engineWorker`/`backends.bot`，行为一行不变；`mode:'off'` 即完全回退 |

**实测效果（整场自对局 10 局固定种子，收窄实现与线上同源）**：

| 指标 | A 关 | L 旧松门槛(≥10种/≥10张、无时机门槛) | **T 新紧门槛 + 时机门槛** |
|---|---|---|---|
| 触发收窄的决策占比 | 0% | **21.9%** | **1.6%** |
| 总胡次数 | 378 | 281（**−26%**） | **383（+1.3%）** |
| **十三幺** | **0** | 5 | **6** |
| 七对 | 112 | 65（−42%） | **112（持平）** |
| 混一色 | 44 | 19（−57%） | **44（持平）** |
| 七星十三烂 | 22 | 9 | **25（+14%）** |
| 最高分均值 | 2723 | 2675 | **2851（+4.7%）** |

结论：**收紧门槛后是"免费的大牌"**——十三幺 0 → 6 次，而总胡次数、七对、混一色全部回到基线（松门槛把资源浪费在"做不成的路线"上，所以反而更差）。决策层不变式同时成立：收窄后 **6/6** 路线局面都保持路线，连"4/4 都选择胡"的 glm 也被引导成打闲牌做十三幺。

**精牌（癞子）与门槛的关系（2026-09-12 实测）**：门槛本身就是**"含精折算后"**的口径，不是固定的自然牌数——持有 J 张可顶替的精牌时，自然牌要求自动下降：

| 持有精牌 | 十三幺需要的自然种数 | 九莲需要的本门自然张数 / 自然花色种数 |
|---|---|---|
| 0 | 12 | 12 张 / 9 种 |
| 1 | 11 | 11 张 / 8 种 |
| 2 | **10** | **10 张 / 7 种** |
| 3 | 9 | 9 张 / 6 种 |

精牌顶替出来的大牌**算番但是软胡**（实测：十二种幺九 + 精当第十三种 → 十三幺 32 倍 320 点 `hardWin=false`；九莲形态 + 精当第 14 张 → 九莲宝灯 32 倍 320 点 `hardWin=false`）。整场实测：10 局做成的 **6 次十三幺里只有 1 次硬胡、5 次靠精顶替** ⇒ 精牌是这条路线的关键使能因素，也说明赔付口径必须区分硬/软：

- `routePayoff` 按 `route.naturalOnly` 折算——自然牌就能完成（13 种幺九齐全 / 1-9 全自然且本门自然 ≥13 张）按硬胡 320 点，必须靠精顶替的按软胡 160 点；
- 效果：软胡路线不再为 80~160 点之间的胡轻易放弃（`160 ≥ 80×2` 仍承诺、`160 < 100×2` 保留小胡）；
- 另有**精牌放宽时机门槛**：持有 ≥2 张精牌时，牌墙门槛从 20 放宽到 15（精多 ⇒ 完成率高 ⇒ 可以更早承诺）。

A/B 复核（10 局固定种子）：v4.1 与 v4.0 的端局数字**完全一致**（触发收窄 20 次 / 1.6%、总胡 383、十三幺 6、七对 112、混一色 44、最高分均值 2851）——这两处改进只在边界情形生效（软胡路线遇到 80~160 点的胡、或残局 + 双精），样本里没有出现，因此属于**防错性质的保守改进：不改变主路径、也无副作用**。




## 公开番型与赌/弃政策（v3，2026-09-12 追加）

问题：v2 只能读牌河，门清大牌最多给弱信号；而**"谁已经胡过什么番型"本来就是公开信息**——`PublicWinScore.items`（番型 id/label）、`patternMultiplier`（倍率）、以及公共批次 `source.tile`（他胡的那张牌），而且血流**首次胡即锁手、那副牌不再改变**。这是比读牌河更确定的依据，此前 AI 完全没有消费（决策只读 `batches[].source.tile` 当作已见牌）。

- **威胁档 = max(牌河读牌, 已公开番型)**：番型倍率 ≥4 / ≥8 / ≥16 → tier 下限 1 / 2 / 3；弱番（平胡一类）**不设档、不设轴**，不因为"对手胡过"就乱防。
- **按番型定逐张危险轴**（`axisSource = 'known'`，**对锁手家同样成立**——已公开番型限定了牌型；而牌河推断的轴（`'inferred'`）对锁手家仍禁用，因为锁手可能是单吊任意听）：

| 已公开番型 | 危险轴 |
|---|---|
| 十三幺 / 字一色 / 清幺九 / 混幺九 | 字牌幺九轴：中张 ×0.25，字牌与幺九照价且公开张数保留下限 0.1（多现 ≠ 安全） |
| 清一色 / 九莲宝灯 / 绿一色 | 花色轴：非嫌疑花色 ×0.5，**哪一门由公开的胡牌牌面确定**（光有番型标签推不出花色） |
| 混一色 | 同上，但字牌算「本门」（不享受非嫌疑花色折扣） |
| 大三元 / 小四喜 / 字一色 | 字牌刻子轴：字牌照价，普通数牌 ×0.5 |

- **兜/弃政策**（`defensePolicy.ts`，用户定稿两条 + 一条赌的出口）：
  1. 打一张即**精吊任意听** → 继续走：锁手后 `engine.ts` 只有"胡 / 摸切"两条路，而任意听时每张摸到的都能胡 ⇒ **从此永不弃牌 = 100% 不再点炮**（哪怕是小牌也值得走）。
  2. **未听牌**（打任何一张都听不上）+ 对手已达十六倍级 → **弃胡兜安全张**：只打最小赔付张、停吃碰杠（本玩法没有查大叫，弃胡没有期末代价）。
  3. **我方上限 ≥ 对手倍率**（可达番型方向按接近度 ≥0.35 取最大 weight）→ 可以赌，继续进攻。
- **方案 c 硬约束**（用户在"只做证据 / 完全交给 LLM / 引擎硬约束"三选一中定稿）：兜牌时在**候选层**收窄，`bloodFlowAiActions` 是同一份事实来源，**引擎与 LLM 共用收窄后的候选**（不会出现"引擎兜、模型放手"的分裂）：撤掉全部吃碰杠候选、弃牌只留放炮成本最小档（`foldDiscardTolerance`）、**胡永远保留**、两个出口不受限。`defense.mode = 'off'` 可一键退回"仅引擎侧选最小赔付、候选不收敛"。
- **LLM 接线**：prompt 新增 `opponentPatterns`（每座位已公开番型 label + 倍率）与 `defense{mode, reasons, ownCanTenpai, ownBestWait, ownAnyWaitReachable, ownCeiling, restricted}`；规则摘要说明"restricted 为真时吃碰杠不会出现，只需在给出的候选里选"。

**实测（必须一起看，避免误判这套政策的效果）**：

| 观察 | 数字 | 含义 |
|---|---|---|
| 兜牌 vs "只按 EV"（同局面只切 `foldThreatTier`） | 抽样 5 手牌 + 3 个 claim 窗口：**弃牌轴差 0 点**（两者都选到最小赔付张），claim 都过 | v1/v2 的赔付定价早已在 netScore 里 ⇒ 兜牌政策的独立价值是：把"最小赔付"从碰巧变成**保证**、stop-claims、给 LLM 的显式信号；**弃牌轴的边际收益小** |
| 硬约束（c）真正的差别 | LLM 座位原本可以挑一个引擎会拒绝的碰/杠，现在该候选**不存在** | 硬约束的价值在**候选空间**，不在排序 |
| 性能 | 硬约束最初让每次决策对每张弃牌跑一次完整向听搜索：12 种子整场 50s → **123s（超时）**；改为"打任意一张是否有听口"判 `canTenpai` 后回到 **57s** | 政策实现必须避免逐张向听搜索 |

**锁手对手的真实赔付结构（2026-09-12 实测，修正了此前"锁手一律同价"的错误说法）**

用 `evaluateWin`（`concealed` 必须**排除**胡的那张，13 张）对四种冻结手牌逐张扫了一遍"我打这张他要付多少"：

| 对手冻结手牌（锁手） | 我打不同牌的实际赔付 |
|---|---|
| 清一色 13 张 | 本门 `p5` = **80 点**；`m5 / s5 / east / red / white / m1` = **0 点（他根本不能胡）** |
| 混一色 13 张 | `p9 / red` = **40 点**；其余 = **0 点** |
| 十三幺形态 13 张 | `p9 / east / red / white / m1` = **320 点**；`m5 / p5 / s5` = **80 点（七星十三烂）** |
| 带精（白板）单吊 4 面子 | `white` = **40 点**；`p5 / p9 / east / red` = **20 点**；`m5 / s5 / m1` = **10 点（平胡）** |

结论：**同一局面最贵 320 点、最便宜 0 点，差 32 倍**；即使是"单吊任意听"的带精手，不同牌之间也有 10 / 20 / 40 点的差别（因为**番型随胡的那张变化**）。所以"锁手就一律同价"是我的模型选择（为了防任意听而取消折扣），不是规则事实。据此校准：

- **已公开番型（`axisSource='known'`）时轴外牌压到 0.1 倍**（`knownOffAxisFactor`）——实测锁手清一色对非本门牌是"不能胡（0 点）"，我们给 0.1 倍（保守不归零，怕他手上有精使轴外牌变成等待）。
- **十三幺/字一色的轴外牌不用这个系数，仍为 0.25**——实测中张仍能以"七星十三烂"胡 80 点（= 320 的 1/4）。
- **锁手家照常吃现档/公开张数折扣**（`known` 轴下 ratio 回到 `ladder`）：他冻结的 13 张里不含已打过的牌，多现的牌更不可能是他的等待。
- 仍保守之处：只有牌河推断（`'inferred'`）而番型未公开的锁手家**保持同价**（信息不足，不猜）。



新模块 `patternPotentials`（纯函数），对 16 番型 + 特殊手输出"接近度 × 权重"：

- 清一色 / 混一色：花色集中度 + 字牌 + 精牌；碰碰胡：对 / 刻 / 精牌计数；字一色：全字牌；九莲：同花色 1112345678999 形态；绿一色：限定牌面子集；清幺九 / 混幺九：幺九与字牌刻；大小三元 / 四喜：箭风刻计数；三 / 四暗刻：暗刻计数；三 / 四杠：已声明杠计数；七对 / 十三幺 / 十三烂 / 七星沿用现有潜力函数（移入新模块供 lotusAi 共用，行为不变）。
- 目标不锁死：每摸一张重估全部方向；`patternBonus = Σ 方向 weight × progress² × 底分 × 局内系数`。
- `estimateWinIncome` 复用同一套计数做完整 14 张的快速番倍估算（封顶 64 / 人）。
