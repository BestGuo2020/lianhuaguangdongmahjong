### 信息减负先落地，再实现字效

先完成[局内信息层级](../rules.md#局内信息层级)，再给确定的内容制作演出。默认内容及出现时机未收拢时，不继续增加新的文字框、标题标签或光效层。

- `GameTableHud.vue`：简化翻精说明和可胡预览；保留精牌身份、首胡锁手后果及完整合法按钮，保护听牌网格和头像次数。
- `BloodFlowWinCard.vue`：区分决策预览与流水详情，保留完整评分数据；不把流水详情的字段原样铺到局内。
- `BloodFlowWinPresentation.vue`：赢家摘要与收入合成一个席位反馈，去掉重复姓名 / 本次变化等说明，不再并排展示五行赢家卡和同笔收入浮层。
- 既有流水组件继续提供完整番型、来源和胡杠账本。减少默认字段不删除记录，不改变支付。

预览示例只表达“清一色·碰碰胡 / 预计 +600 · 自摸 · 硬胡”，首次可胡附简短锁手提示。已经发生的结果不再标预计；若本次收益与其他收付合并，明确标“合计”，不能混成一个未说明含义的金额。

### 先完成一个代表性高番，再覆盖所有事件

先在 llmAnime 的单次本家高番上完成可复用标题：笔画与字距、字面 / 描边 / 厚边、透视及冲击，配合现有角色和光柱。起势与阅读可留时间，重拍保持短促；不以整段等比放慢代替运动设计。字体与材质应覆盖全部牌型，不能只把“绿一色”写成特殊分支。

阶段交接以优先视频为准：来源确认 → 角色 / 动作 → 主番重拍与楼位强调 → 稳定阅读 → 分席位收付 → 交回操作。使用已有共享时钟安排，允许必要的短交叠，但主字不能被角色遮挡，不再建立第二套并行队列。

单次演出正常速度与关键帧自检通过后，再覆盖他家胡、本家放枪、两响 / 三响、重复胡及五主题。多响共享一次提示，各赢家分别有主番和收益；主提示可结合来源位置，不要求所有信息都居中。不得为表现一致让未获胜的付款者播放胜利立绘。

## 1. 这轮只补游戏表现

- 范围：结算窗口关系与按钮、最终排名、本局结算、胡牌字效、飞牌落楼、多响、正负分反馈、五主题以及局末感言的呈现位置。
- 不调整玩法、番型分值、硬胡、底分、封顶、首胡锁手或 AI 决策策略；不纳入性能优化、安全审计、后端开发或新的联机架构。
- 保留现有两骰 / 翻精 / 发牌；保留已经恢复的 3D 光束、粒子和原胡牌位。
- 保留持续向上盖楼，不恢复旧方案的三层 / 两层截断。
- 复用现有胡 / 自摸 / 吃碰杠报声代码、资源和角色音色；不新增替代报声、不双播。
- 局内胡牌无自由感言；正常摸打、吃碰杠的已有 LLM 动作短句与气泡应保留，不能一并关闭。只有 llm / llmAnime 在本局结束后允许全桌感言；其他三个主题无角色感言。
- 用户所说“结算混乱”的直接反馈是按钮返回不通，不把此前关于分数理解的推测当成新的用户需求。结算外观补齐必须保持已修复的操作路径。
- 不从“莲花”地名推导花卉、地域装饰或世界观。参考视频的动作节奏，不复制其金额、充值流程、角色或完整 UI。

### 1.1 本轮补充：立绘、声音、动作气泡

用户询问 `llmAnine`，本方案按现有主题 ID `llmAnime` 理解。

- `llmAnime` 的胡牌演出包含获胜席位的角色立绘，立绘与字、光、飞牌、数字共享同一 cue。优先复用 `AnimeActionCue.vue` 的角色选择、动作图与回退资源，沿用已确认的立绘尺寸和席位锚点；不把桌布固定人物当成玩家。
- 本轮明确接入非人声胡牌效果音，优先复用已有 `public/audio/hu_effect_sound.mp3`，与落牌 / 标题重拍同步。它与原“胡 / 自摸”等人声报声是两个通道，不替换或重复原报声。
- E14 立项时已有 `audioBridge.ts` 人声接线、缺非人声效果音；实现及实听状态分别见任务表和验收记录。用户报告“听不到胡牌音效”时，两类声音分别验收；不能因代码调用或 spy 通过就认定实际可听。

## 4. E10：结算宿主与按钮路径

现有文件：`src/components/table/GameTableHud.vue`、`src/components/settlement/BloodFlowRoundLedger.vue`。拟新增：`BloodFlowSettlementHost.vue`、`BloodFlowRoundSummary.vue`、`BloodFlowFinalRanking.vue`。优先抽取旧结算可复用的布局 / 主题样式，不整文件替换原 `SettlementOverlay.vue`。

- **E10-1** 用一个宿主管理 `table / round / final / details` 四种展示状态和明细返回目标。只能有一个可交互结算层，不叠两个遮罩。
- **E10-2** 保留 fc86da7 的按局 ID 自动打开一次。× 和“查看牌桌”均回到 table，桌面保留“返回结算”；明细另有明确的“返回结算 / 返回牌桌”按钮，不依赖用户猜 × 的含义。
- **E10-3** 非末局打开本局结果，末局打开最终排名；最后一局结果可从最终页主动查看，不能自动连续弹两页。
- **E10-4** 本局页沿用既有头像、昵称、本家标识、正负分和当前积分的展示语言；胡牌次数、胡牌收支、杠牌收支保留为辅助信息和详情，不删除账本信息。
- **E10-5** 最终页按权威累计总分 / 排名展示四家，不能把最后一局 delta 当整场分数。没有完整场次历史时不伪造“全场逐局回放”。
- **E10-6** “继续下一局”只推进一次，并接入既有权威准备状态显示等待；“返回大厅”只离场。失败时保留可恢复路径，不能因本机按钮标记永远锁住。不要用纯计时器假装其他玩家已准备。

通过条件：普通局、末局、无胡局、有席位筛选的流水均能“结算 → 牌桌 → 结算”；按 × 后同局新对象不重弹；进入下一局清理旧入口；P2P 等待时仍可查看牌桌并返回。原 `blood-flow.settlement-navigation.spec.ts` 全部保留。

提交建议：`feat: complete blood-flow settlement views and navigation`。

## 5. E11：统一胡牌表现调度

现有文件：`src/game/variants/lotus/bloodFlow/presentation.ts`、`BloodFlowWinPresentation.vue`、`three/bloodFlowWinEffects.ts`、`GameTableHud.vue`、`MahjongTable3D.vue`。拟新增：共享 `presentationDirector.ts` 及只读 cue 类型。

- **E11-1** 每个观看端只保留一个调度器创建 cue，DOM 与 3D 消费同一 `cueId / batchIds / startedAt / duration / phaseMarks`，不各自 next 一次队列。
- **E11-2** cue 包含绝对来源席位、动作种类、赢家逐席番型摘要、逐席收付向量和展示记录 ID。局部坐标在观看端转换，牌实体账不读取 cue。
- **E11-3** 明确 `focus / impact / readable / score / exit` 时间节点。先统一节拍，再调字形与粒子，避免不同模块各自写 setTimeout。
- **E11-4** 同席同主番记录完整演出冷却；更高番或另一家首次大番可完整出现。中央舞台仍排队，不能同时塞多个中央标题。
- **E11-5** 连续批次积压时，合并 cue 的收付必须是所有包含批次的实际合计；若显示最后一笔金额，必须明确标注最后一笔，不能用“多次胡牌”标题配未说明的单笔数字。
- **E11-6** 恢复 / 重连只构建最终展示态，不重播历史 cue。单机阶段、下一动作开放及倒计时共用明确的时间安排；旧 450ms 默认值已由可玩性修复调整，不作为不可变约束。装饰动画 / TTS 回调不直接提交规则动作；新动作开放后，收尾画面不能遮操作区域。
- **E11-7** `llmAnime` 增加受 cue 控制的角色层：绑定获胜席位 / 角色 ID / 胡牌动作种类；角色入场、主字重拍、飞牌落点与退场用同一时间安排。不能只取消旧胡牌立绘屏蔽，让旧 CSS 时间线与新演出双播。

通过条件：给定同一时间输入，角色立绘、文字、光效、飞牌和数字对应同一批次 / 记录；连续十胡及中途新批次到达不串台；多响各角色对应正确玩家；普通吃碰杠立绘照常工作。调度器不能调用计分、摸牌或再次触发现有动作报声出口。

提交建议：`refactor: share blood-flow presentation timing across renderers`。
