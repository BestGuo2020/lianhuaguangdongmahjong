### 信息减负先落地，再实现字效

先完成[局内信息层级](../rules.md#局内信息层级)，再给确定的内容制作演出。默认内容及出现时机未收拢时，不继续增加新的文字框、标题标签或光效层。

- `GameTableHud.vue`：简化翻精说明和可胡预览；保留精牌身份、首胡锁手后果及完整合法按钮，保护听牌网格和头像次数。
- `BloodFlowWinCard.vue`：区分决策预览与流水详情，保留完整评分数据；不把流水详情的字段原样铺到局内。
- `BloodFlowWinPresentation.vue`：主番在读字阶段展示一次，收付阶段只留每席正负金额；去掉赢家摘要卡、底框及重复番型 / 倍率 / 胡牌方式，多笔合并只加“合计”。
- 既有流水组件继续提供完整番型、来源和胡杠账本。减少默认字段不删除记录，不改变支付。

预览示例只表达“清一色·碰碰胡 / 预计 +600 · 自摸 · 硬胡”，首次可胡附简短锁手提示。已经发生的结果不再标预计；若本次收益与其他收付合并，明确标“合计”，不能混成一个未说明含义的金额。

### 先恢复公共表现，再完成一个代表性高番

以下代表性高番工作必须在下述“公共表现收拢”完成之后开展。已做过的字形实验保留为证据，不意味着当前可以继续沿血流独立动作、独立飞牌路径扩建。

先在 llmAnime 的单次本家高番上完成可复用标题：笔画与字距、字面 / 描边 / 厚边、透视及冲击，配合现有角色和光柱。起势与阅读可留时间，重拍保持短促；不以整段等比放慢代替运动设计。字体与材质应覆盖全部牌型，不能只把“绿一色”写成特殊分支。

阶段交接以优先视频为准：来源确认 → 角色 / 动作 → 主番重拍与楼位强调 → 稳定阅读 → 分席位收付 → 交回操作。使用已有共享时钟安排，允许必要的短交叠，但主字不能被角色遮挡，不再建立第二套并行队列。

单次演出正常速度与关键帧自检通过后，再覆盖他家胡、本家放枪、两响 / 三响、重复胡及五主题。多响共享一次提示，各赢家分别有主番和收益；主提示可结合来源位置，不要求所有信息都居中。不得为表现一致让未获胜的付款者播放胜利立绘。

### 后续公共布局调整：副露后移与右手角胡牌位

用户在五包完成后新增的方案要求；本节仅为实施设计，不表示已改代码。此前两个决策话题暂后置。本次改动适用于非血流与血流，五主题共用几何布局，非血流放本次胡的一张，血流继续盖楼。

**视频复核。** 本次实际查看优先视频对应的 `self-draw.jpg`（1:58～2:03.5）与 `multi-summary.jpg`（5:49.5～5:54）连续帧。本家胡牌楼在手牌右前方、下方与右侧牌墙端部附近；自摸新牌经手部演出放到该楼顶，后段连续胡仍在同一区域垒高。其他角落也能看到积累牌，支持采用四家各自角落的布局。画面有透视、手部和直播遮挡，不据此虚构精确世界坐标；不复制视频手模型、牌规或层数限制。

**方向定义。** “往后”解释为副露带朝所属玩家一侧、远离桌心移动；“右手边”按玩家面向桌心的局部方向，而非观察者统一屏幕右侧。若本家处于屏幕下方：

| 席位 | 副露后移方向 | 胡牌角落 |
|---|---|---|
| 本家（下） | 屏幕下方 | 右下 |
| 右家 | 屏幕右方 | 右上 |
| 对家（上） | 屏幕上方 | 左上 |
| 左家 | 屏幕左方 | 左下 |

**空间关系。** 胡牌位使用两面牌墙交汇处靠桌内的独立预留区，不直接压在活牌墙上；牌墙逐渐摸空后锚点也不移动。副露放在靠玩家的后侧带，从右手角预留区外开始向自身左侧展开。胡牌区与副露第一组必须留出间距，不能只把旧胡牌坐标平移到副露起点造成重叠。

**公共实现。**

1. 从现有副露/牌墙坐标定义中提取一份公共席位布局，提供局部左右轴、向外轴、副露轨道、胡牌角落与安全边界；沿用 `winDisplayLayout` 等入口委托它，避免 HUD、普通胡、血流楼分别写四组常量。布局依赖桌面几何和视口，不由主题或牌墙剩余数量决定。
2. `meldTransform` 与暗手让位计算共同消费副露轨道。当前 `addConcealedHand` 内的副露跨度/让位常量也要一起收拢；不能只改副露而让立牌挤在旧位置。保留横牌方向、底边对齐、补杠附牌和已存在的副露动画。
3. 先试后移约半个牌深，以一张牌深作为第二档对照；这是项目试调尺度，不是视频测得数值。胡牌区与牌墙/副露的初始余量按约半个牌宽试调，最终按四副露与高楼画面决定。四家局部规则一致，透视下允许已有布局参数微调，不硬套四个相同屏幕像素。
4. 普通 `winEffectPresenter` 与血流 `bloodFlowWinPiles` 共用右手角锚点。普通只展示一张真实胡牌；血流首张采用同一落点，其余牌从固定起点沿席位局部方向填充，满层上叠。保留桌面4张/层、小屏3张/层与持续向上，不增加上限。
5. 当前血流按一整层宽度对锚点做居中偏移，迁移时须改为明确的“首张锚点＋整层占地”，否则普通单张与血流首张仍不在同一位置。整层占地预先留足，不随牌数增长左右漂移。
6. 飞牌目标、落点光柱/粒子、普通胡最终静态牌、血流楼层牌同步使用新布局。抢杠来源继续从实际副露位置计算。复用公共运动函数和现有时钟，仅改来源/目标，不能重写轨迹或改变播放时长。
7. 牌型标题与飘分仍按各自席位的信息层级，不全部跟着挤进角落；头像次数入口保留。自摸胡牌从暗手分离仍只一次，点炮/抢杠保持原实体归属。

**实施顺序与验收。** 先做无演出静态布局，验证四家无副露、1组、4组副露及普通单胡；再接血流1/4/5/13/25/41张，验证层满换层与固定首张位置；最后验证自摸、点炮、抢杠、多响的飞牌和光柱。五主题在1280×720、844×390、568×320逐项检查，四家切换为本家视角后归属仍正确。底部手牌/操作按钮、其他三家立牌、补杠牌、牌河晚局扩展和楼顶不能互相遮挡；不可为了避让截断楼层或删牌。长楼遮挡先通过预留区位置和整层朝向处理，现有尺寸与叠层规则保留。

交付同输入的布局前后截图及原速落牌片段，同时跑普通模式/血流的副露、单胡分牌、跨层、来源和小屏回归。不重新启动旧五包，不要求本轮处理后置的决策问题、P2P或后端。

### 执行包 3：节奏和信息交接（E11 / E13 / G02～G05）

使用已有 director 的唯一时钟安排：来源确认 → 原动作/获胜角色 → 飞牌落楼与主番重拍 → 稳定读番 → 一次收付 → 开放下一操作。动作可以有短交叠，但角色不能遮主字，旧结果不能覆盖下一轮操作预览。

- 普通摸打与吃碰杠继续原阶段和报牌等待；本轮不把所有动作统一延迟，也不以整段等比减速制造可玩性。
- 分别测量“牌可辨认的时间、主番稳定可读时间、下一操作开放时间”。在当前时长基线上调整阶段占比；需要调整总时长时记录原速前后片段及原因。主番阅读先试约 500～800ms，属于试调值，不能直接覆盖普通动作时长。
- 锁定/禁操作仅覆盖必要的当前演出及摸牌阶段；进入有效响应后显示全部合法候选，不能为了降低密度藏碰/杠或强制先过。启用倒计时的实例从可操作时开始计时，保持默认大厅无倒计时配置。
- 日常仅保留牌桌、局况、头像积分/次数、精牌身份和必要提示；详细规则与账本主动打开。动作阶段不显示赢家摘要卡；主番只说一次；收付每席一次正负数，多笔合并才加合计。
- 明确分开“上一事件已发生收付”和“当前预计收益”。不能用继续增加标签解决两个事件同时占主区域；优先错开出现时段。
