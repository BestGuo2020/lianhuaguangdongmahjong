# 大模型麻将疑难局面评测集建设规范

> 版本：v0.1（建设方案）  
> 适用玩法：`lotus-classic`（仅自摸与抢杠胡的莲花广麻）、`lotus-legacy`（莲花麻将）  
> 目标：判断快速模型、条件深思和旗舰模型是否真正改善决策质量，而不是比较台词、模型自述或通用榜单。

## 1. 要回答的问题

评测集必须能稳定回答以下问题：

1. 条件深思相对快速模式，在疑难局面中是否减少次优选择和灾难性错误？
2. 提升计入超时回退后是否仍然成立？
3. 哪些触发器真正值得消耗深思次数，哪些只是增加延迟？
4. 快速模型是否已经达到上线目标，是否有必要让旗舰模型进入在线链路？
5. 两种玩法应分别使用什么阈值，不能用一个总胜率掩盖规则差异。

评测对象只包括 `choice` 所代表的实际动作。自由生成的 `message`、性格台词和语音表现不计入牌力分数。

## 2. 基本原则

- **玩家视角**：样本只能包含决策者当时可见的信息，不得泄露牌墙顺序、对手暗手或后续摸牌。
- **引擎限定动作**：合法候选由当前规则引擎生成；模型只在候选中选择，评测不要求模型重新判断合法性。
- **一例一决策**：每条样本只评价一次 `turn` 或 `claim`，避免把整局输赢错误归因到某一步。
- **允许多解**：麻将经常存在多个近似等价动作，标签必须支持“最佳、可接受、明显次优、灾难性”四档，而不是强迫唯一答案。
- **可复现**：记录协议版本、规则版本、候选、随机种子和标注依据；同一版本应能重新生成同样的候选。
- **人类最终负责**：旗舰模型可以提供盲审建议，但不能作为唯一真值；不保存模型思考过程，只保存最终选择和简短可审计理由。
- **分玩法报告**：`lotus-classic` 不评价普通防铳；`lotus-legacy` 才评价牌河、副露、染手和巡目构成的危险度。

## 3. 数据来源

按可信度和用途组合四类来源：

| 来源 | 主要价值 | 约束 |
|---|---|---|
| 历史缺陷与玩家反馈 | 高价值回归案例，例如碰后打回、可杠却碰、庄家身份和摸牌来源误判 | 每个已修复缺陷至少保留 1 个最小案例 |
| 自愿采集的真实对局 | 保留自然牌河、巡目和对手行为分布 | 必须去除玩家身份、昵称、聊天、房间号和时间戳 |
| 引擎搜索生成 | 定向覆盖候选接近、杠前后听口、末巡和分差压力 | 生成器不得把未来牌序写入模型输入 |
| 高手手工构造与对抗样本 | 覆盖罕见但重要的陷阱、染手伪装和多候选防守 | 必须通过规则引擎合法性与可达性检查 |

不得采集或写入 API Key、完整请求头、用户账号、语音、自由聊天和模型的隐藏推理内容。

## 4. 样本结构

建议采用 JSONL；一行是一项独立决策。标签使用规范动作键，不只保存 `A1` 等临时候选编号，以免候选排序调整后标签失效。

```json
{
  "datasetVersion": "0.1.0",
  "caseId": "legacy-defense-0001",
  "schemaVersion": 1,
  "ruleCode": "lotus-legacy",
  "decision": "turn",
  "state": "与 DecisionRequest.state 同形状的脱敏快照",
  "candidates": "引擎生成的完整候选及特征",
  "engineSuggestion": "A3",
  "scenarioTags": ["late-round", "three-meld-threat", "flush-tendency", "close-candidates"],
  "provenance": {
    "kind": "regression|real|generated|expert",
    "sourceId": "不可反查用户的内部编号",
    "generatorVersion": "可选",
    "seed": 12345
  },
  "label": {
    "bestActions": ["discard:s7"],
    "acceptableActions": ["discard:s7", "discard:east"],
    "actionScores": {
      "discard:s7": 100,
      "discard:east": 92,
      "discard:m5": 55
    },
    "catastrophicActions": ["discard:m5"],
    "reasonCodes": ["opponent-flush", "late-round-safety"],
    "confidence": "high",
    "adjudication": "consensus|adjudicated|provisional"
  }
}
```

`actionScores` 使用 `0～100` 的相对质量分，只在同一样本内比较，不解释为胜率。第一版控制理由词表，建议包括：

- `hand-efficiency`：向听数、进张和剩余有效牌；
- `wait-quality`：听口数量、剩余张数和特殊牌型；
- `claim-value`：吃碰后结构、后续最佳弃牌与门清代价；
- `kong-value`：即时杠分、补摸、破坏听牌和抢杠风险；
- `opponent-flush`、`opponent-meld-pressure`、`discard-order-risk`：仅用于允许普通防铳的玩法；
- `late-round-safety`、`placement-pressure`：残局和名次压力；
- `wildcard-preservation`：白板癞子、精牌和替代牌保护；
- `rule-forced`：规则或已证明的严格支配关系。

## 5. 首版样本配额

### 5.1 种子回归集：50 例

先用两周左右建立小而可靠的 50 例，验证格式和标注流程：

| 类别 | 数量 | 说明 |
|---|---:|---|
| 历史 bug 回归 | 15 | 已发生过的动作/台词上下文错误，动作标签优先 |
| 候选接近 | 10 | 前两名评分差小，测试条件深思核心价值 |
| 吃碰杠取舍 | 10 | 直杠与碰、碰后弃牌、吃后结构、补杠/暗杠 |
| 癞子与特殊牌型 | 8 | 白板、双精、乱风杠、特殊听牌 |
| 残局与分差压力 | 7 | 末巡、领先防守、落后追分；按玩法区分防铳 |

种子集通过质量闸门后，冻结为永久回归集；不能为了让新模型分数更高而删除失败样本。

### 5.2 MVP 评测集：300 例

- `lotus-classic`：120 例，重点是牌效、杠收益、癞子保护、末巡与抢杠相关结构。
- `lotus-legacy`：180 例，除上述内容外增加副露、牌河顺序、巡目、染手倾向和危险牌。
- 每种玩法中 `turn` 不低于 70%，`claim` 不低于 20%，其余留给特殊响应与回归案例。
- 每个主要标签至少 15 例；任何单一来源不超过总量的 50%。
- 相同整局派生的多个决策必须进入同一数据分区，防止相邻巡目泄漏到测试集。

## 6. 标注与裁决

### 6.1 三层证据

1. **规则证据**：合法性、向听数、进张、等待牌、杠分和严格支配关系由引擎计算，人工不得凭印象改写。
2. **模拟证据**：需要比较长期收益时，在固定隐藏信息生成策略和随机种子下做多次 rollout；报告均值、方差和样本数，不能只留一个结论。
3. **专家判断**：处理对手倾向、牌河时序、名次目标等难以完全建模的部分。

### 6.2 双人盲标

- 至少两名标注者独立作答，作答时隐藏引擎建议、模型名称和其他标注者意见。
- 两人最佳动作一致，或互相落在对方的“可接受动作”内，可形成共识标签。
- 若一方把另一方选择标为明显次优或灾难性，交由第三人裁决。
- 旗舰模型可作为第四份匿名意见；它的意见不得覆盖两名人类与规则证据。
- 只保存简短理由和理由码，不要求人类或模型提供逐步思维链。

### 6.3 标签置信度

- `high`：规则严格支配，或专家一致且模拟差距稳定；
- `medium`：存在多个接近选择，但可明确划分可接受集合；
- `low`：专家持续分歧或模拟方差过大，只进入研究集，不进入上线闸门。

## 7. 去重、泄漏与数据划分

- 以“规则、手牌多重集、副露、牌河、巡目、候选动作集合”生成结构指纹，过滤完全重复和近重复样本。
- 对同一样本生成候选顺序置换副本，只用于检测位置偏差，不重复计入总分。
- 按来源整局分组后划分：校准集 60%、隐藏测试集 25%、永久回归集 15%。
- 校准集可用于调 prompt、触发阈值和特征；隐藏测试集在发布前才运行，不允许据其单例反复改 prompt。
- 发布报告必须写明数据集版本、代码提交、模型精确名称、供应商、思考参数和截止时间。

## 8. 评测矩阵

同一冻结数据集至少比较四条路径：

| 路径 | 用途 |
|---|---|
| 引擎建议 | 确定性基线与超时回退结果 |
| 快速模型、思考关闭 | 日常在线路径 |
| 同一模型、条件深思 | 测量思考本身的增益 |
| 旗舰模型、较宽离线预算 | 估计质量上限和发现标注争议，不直接代表可上线效果 |

模型有采样随机性时，每个样本至少重复 3 次，并使用固定的候选顺序组和顺序置换组。比较模型时必须使用同一 prompt 版本、同一候选和同一截止规则。

## 9. 核心指标

| 指标 | 定义 |
|---|---|
| 合法输出率 | 能解析且命中候选白名单的比例 |
| 最佳动作命中率 | 命中 `bestActions` 的比例 |
| 可接受动作率 | 命中 `bestActions ∪ acceptableActions` 的比例 |
| 平均遗憾值 | `100 - 所选动作 actionScore`，越低越好 |
| 灾难性错误率 | 命中 `catastrophicActions` 的比例 |
| 有效决策质量 | 超时、HTTP 错误和非法输出按实际回退动作计分，不能从统计中剔除 |
| 深思增益 | 同一模型深思与快速模式的有效质量差 |
| 触发器精度 | 被触发样本中，深思确实改善动作的比例 |
| 触发器召回 | 所有“深思可改善”样本中，被当前规则触发的比例 |
| 延迟与成本 | P50/P95、超时率、平均输入/输出/推理 token 和单局估算成本 |

除总表外，必须按玩法、场景标签、巡目、动作类型和置信度分层报告。总胜率只能作为长期模拟的辅助指标，不能替代逐决策指标。

## 10. 初始上线闸门

以下阈值是 MVP 起点，积累真实数据后再校准：

- 条件深思相对快速模式：高/中置信度样本的可接受动作率提升至少 3 个百分点，或平均遗憾值下降至少 10%。
- 灾难性错误率不得上升；规则严格支配样本不得出现新增错误。
- 计入回退后的超时率不高于 5%，在线 P95 不超过对应 `deadlineMs`。
- `lotus-classic` 与 `lotus-legacy` 分别过闸，不能用一项玩法的提升抵消另一项下降。
- 若旗舰模型要进入在线升级路径，必须在最高难度子集上比当前条件深思再提升至少 5 个百分点，并在同一截止时间内仍保持有效增益。

未过闸时，优先改进状态特征、危险度推断、候选评分和触发器；不要仅通过延长思考时间掩盖输入信息不足。

## 11. 质量闸门

每次冻结数据集版本前检查：

- [ ] 所有状态均通过当前规则引擎重放并能生成记录中的候选；
- [ ] 没有未来信息、用户身份、聊天、Key 或模型隐藏推理；
- [ ] 每条正式样本有两份独立标注，冲突样本完成裁决；
- [ ] `bestActions`、`acceptableActions` 和 `catastrophicActions` 互不重叠；
- [ ] 每个动作分数在 `0～100`，最佳动作至少一个且为 100；
- [ ] 低置信度样本不参与上线闸门；
- [ ] 近重复样本和整局泄漏已检查；
- [ ] 数据集版本、规则版本和生成脚本版本可追溯。

评测数据默认不进入浏览器生产包；付费模型评测不放入普通单元测试和每次 CI，使用显式离线命令运行。永久回归集中的规则与候选生成验证可以进入 CI，模型调用部分按版本发布或人工触发。

## 13. 分阶段实施

1. **P0：格式与量表**——确定 JSON Schema、动作规范键、理由词表和脱敏规则。
2. **P1：50 例种子集**——移植历史 bug，邀请两名熟悉玩法的人完成双盲标注，打通单份报告。
3. **P2：300 例 MVP**——加入真实局面、生成局面和高手构造，冻结隐藏测试集。
4. **P3：自动评测器**——批量运行引擎、快速、条件深思与旗舰模型，统一统计超时回退、质量、延迟和成本。
5. **P4：持续扩充**——把线上争议局面和新缺陷先加入待裁决池，完成标注后进入下一个数据集版本。

最先应完成的是 P0 和 50 例种子集。没有可靠标签和有效质量指标前，不以旗舰模型替换当前在线快速模型。
